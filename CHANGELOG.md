# Changelog

## Unreleased

### Breaking

- **ratatui:** `Content::renderer` now chooses the Cell Renderer per cell, from the row Key and the column Key, as the web's `RendererChoice` does, so a column-major table can draw each row its own way. A host that chose by column renames its `renderer(&self, col)` to `column_renderer(&self, col)`, which the default `renderer` calls. `fit_width` asks each cell's own renderer.
- **core:** a Sort header click on a row header now sorts the columns by that row, as a column header click sorts the rows (it did nothing before). Row headers keep `HeaderClick::Select` by default.
- **memory:** `InMemoryTableSource::apply_sort` and `sort_spec` take the axis, so either axis sorts. `MemorySource::view`, `changed`, `edited` and `replaced` return each axis's Change Notices as `Vec<(Axis, ChangeNotice)>`, since sorting the columns by a row makes a row's change move the columns. The testkit's `RecordTable` and `ColumnMajorTable` `edit` and `replace` follow. A sort now starts from the order column moves left, so ties keep it, and a move on sorted columns makes that order the columns' own and clears their sort.
- **memory:** the In-Memory Table Source filters either axis: `apply_filter(axis, keep)`, `clear_filter(axis)`, `filtered(axis)`, `refilter_item(axis, item, keep)` and `defer_item(axis, item, keep)` replace the rows-only calls, and `position(axis, item)` replaces `row_position` (`base_rows` goes too, for `base_len(axis)`). `MemorySource::appended` returns `Vec<(Axis, ChangeNotice)>` as well, since filtering the columns by a row makes new rows refilter the columns, and `distinct` takes the axis. A move's drop Position is read in the filtered order.
- **wasm:** `WebMemory::sort` takes the axis first.
- **core:** picks are kept per axis: `Selection::picks` is `[Vec<Key>; 2]`, and `picked`, `toggle_pick` and `Snapshot::picked` take the axis. Ctrl/Cmd-click on a column header picks the column under Sort or Select, as on a row header; under `SelectionUnit::Cols` a Ctrl/Cmd-click on a cell picks its column.
- **core:** a `Reset` keeps the Size Overrides of both axes with their Keys (rows lost theirs before), and a `Removed` drops those of the removed Keys on both axes (columns kept theirs before).
- **C API:** the picked Keys move from `BinnacleSnapshot` to `BinnacleAxisSnapshot` (`picked`, `picked_len`), one list per axis.
- **web:** `SelectionChange.picked` is `{ rows, cols }` of IDs and `FrameInfo.picked` is `{ rows, cols }` of counts.
- **ratatui:** `ColumnFilter::fetch` asks with the axis too (`|axis, key, query| ...`), and `Control` gains `RowFilter`.
- **web:** `WebMemory`'s filter calls take the axis first.
- **core, web, C API:** each axis's part of a View Spec gains `hidden`, the Keys (IDs on the web) of its own items to leave out, so a Table Source that builds parts by hand adds it (`AxisView::default()` has none). On the web `AxisView` and `AppliedAxisView` take the axis's own ID type second.
- **testkit:** `append` on `RecordTable` and `ColumnMajorTable` returns `Vec<(Axis, ChangeNotice)>` too.
- **core:** `Snapshot::headers` places the headers of every drawn item, the leading pinned Strip's first, then the scrolling Strip's; `Snapshot::rows` and `cols` stay the scrolling Strips. A host that zips `rows()` with `headers(Axis::Rows)` iterates `drawn(Axis::Rows)` instead.
- **C API:** `BinnacleAxisSnapshot.strip` lists the drawn items, the `pinned_len` pinned ones first, and gains `scrolling_start` and `scrolling_end`; the cell states run over the drawn items.
- **ratatui:** `Theme` gains `pinned_edge`, so a Theme built field by field names it (or takes `..Theme::classic()`).
- **web:** `AxisSnapshot.strip` lists the drawn items, the `pinned` ones first, and gains `scrolling`. `Theme` gains `pinnedEdge` and `pinnedShadow`. The `Action` union gains `Pin` and `Unpin`. The column menu opens on every column, not only those that take conditions; one that takes none shows only its pin button.
- **core:** header drags move items only on an axis the Table Source declares movable with `Grid::set_movable`, row headers as well as column headers; no axis is movable until declared (`pump` declares it from `PumpSource::movable`). A requested move stays pending until `Grid::move_answered`, and no other move starts meanwhile.
- **memory:** `PumpSource::move_items` returns `Result<Moved, String>`: the Change Notices and any View Spec the move left, or a short reason to refuse. `InMemoryTableSource::move_columns` and `MemorySource::move_columns` become `move_items(axis, keys, to)`, which move either axis and return `None` when refused.
- **web:** a Table Source axis without `move` offers no move: dragging its headers no longer starts one.
- **core:** `Edge` gains `Trailing` and is no longer `#[non_exhaustive]`. The selection range is contiguous in drawn order, so with items pinned it covers several runs of Positions: `CellRange` holds sorted runs per axis (`span(axis)` and `covers(axis, p)` read them), and `Snapshot::selection_range` returns a reference. Arrow keys step in drawn order across the pinned and scrolling Strips. `Snapshot::headers` and `drawn` end with the trailing pinned Strip.
- **C API:** `selection_range` becomes `selection_runs` and `selection_runs_len` (each run a row or column `start` and `end`), and `BinnacleAxisSnapshot` gains `trailing_len`, the trailing pinned items that end `strip`.
- **web:** `Snapshot.selectionRange` and `FrameInfo.selection` hold each axis's runs (`Span[]`), and `onSelectionChange` lists a range's IDs in drawn order. `AxisSnapshot` gains `trailing`. `GridWidget.pinned(axis, edge)` takes the edge (leading by default). The `Action` union gains `Freeze`. The row menu opens on every row too, with its pin buttons.
- **ratatui:** `Control::ALL` holds 32 Controls, and `begin_frame` sets each axis's Edge Gap to one cell.
- **core:** `Grid::hide` returns `Result<(), HideCapped>`: a hide that would leave more of an axis's items hidden than its cap hides nothing and asks for nothing ([#149](https://github.com/flotilla-org/binnacle/issues/149)).
- **ratatui:** `HeaderMenu::key` takes `keys_at`, the Keys of a run of Positions from the Table Source, since its Hide and "Show only" act on the picks or the selection. `Control::Hide` hides the chosen items (the picks, else the selection, else the focused item), and the menu is 40 cells wide.
- **web:** `GridWidget.hide` returns `false` when the hide passed the axis's cap. `FrameInfo` gains `hideCapped`, the `Action` union `OpenChooser`, and `InputHost` `openChooser`. The Hide key hides the chosen items, not only the focused one.
- **core:** dragging headers across the pinned edge ([#153](https://github.com/flotilla-org/binnacle/issues/153)): a header drag starts on every axis, movable or not, since pinning is the Grid's own. `Mode::MovingHeaders` carries a `target` and `DropIndicator`'s `to` becomes `target`, a `DropTarget`: `Move { to, unpin }`, `Unpin { at }`, `Pin { edge, before, reorder }` or `Stay`, which draws no line. A pinned header drags alone.
- **C API:** `BinnacleSnapshot` gains the drop target (`drop_target`, `drop_position`, `drop_unpin`, `drop_edge`, `has_drop_before`, `drop_before`, `drop_reorder`) and the lit pin zones (`pin_zones`, `pin_zones_len`); `BINNACLE_MODE_MOVING_HEADERS` names the mode.
- **ratatui:** `Theme` gains `pin_zone` and `pin_zone_hot`, and `begin_frame` sets each axis's pin zone to one cell.
- **web:** `Mode`'s `MovingHeaders` and `Snapshot.dropIndicator` carry a `target` (a `DropTarget`) in place of `to`, and `Snapshot` gains `pinZones`. `Theme` gains `pinZone`.
- **C API:** `BinnacleAxisSnapshot` gains `leading_start`, `leading_end`, `trailing_start` and `trailing_end`, where the pinned Strips draw, after `scrolling_end`.
- **web:** `AxisSnapshot` gains `regions` (`leading` and `trailing` spans): a pinned item draws clipped to its Strip's region, no longer from the Header Band to the viewport's end.
- **ratatui:** `begin_frame` also keeps `MIN_SCROLLING` cells of each axis to scroll (3 lines, 12 columns), so pinned Strips longer than the rest clip.

- **core:** `Effect` gains `PinsChanged`, so a host matching every Effect adds an arm (or a wildcard).
- **C API:** `BinnacleEffect` gains `edge` (for `BINNACLE_EFFECT_PINS_CHANGED`), and `BinnacleAxisSnapshot` gains `leading_pins`, `leading_pins_len`, `trailing_pins` and `trailing_pins_len` after `hidden_len`.
- **memory, web:** the In-Memory Table Source (`MemorySource`, `fromRows`) leaves out a sort term naming a column or row the data lacks and answers with the rest, as it prunes unknown hidden Keys, where it rejected the whole View Spec before (`Unsortable`, or a thrown error). A column it has but cannot sort is still refused. A restored layout naming a column the table lost keeps its other parts.
- **memory:** `MemorySource` leaves a condition on an item of the other axis the table lacks out of its answer, on either axis, so it shows as not applied (as `fromRows` already did); it applied it before, reading blanks, which kept no rows. Appending the item later does not apply it again until the View Spec is re-applied.
- **web:** the `Effect` union gains `PinsChanged`, and `AxisSnapshot` gains `pins` (`leading` and `trailing` Keys, dormant ones included).

### Added

- **core:** a header dropped into a pinned Strip pins its item there, before the pinned item under the drop's first half (reordering if it was pinned there already); an empty Strip takes the drop over its pin zone, the Header Band or past the viewport's far end, and `Snapshot::pin_zones` lights those zones while a header is dragged. Dragged out, a pin unpins and, on a movable axis, asks to move to the drop Position (a refused move leaves it unpinned in its own place); elsewhere it returns to its own place, which the drop line marks. `Grid::set_pin_zone` sizes the zones (a quarter of the axis's default item size until set; 0 turns empty-Strip drops off).
- **C API:** `binnacle_grid_set_pin_zone`. **wasm/web:** `WebGrid.set_pin_zone`; the widget lights the zones, captions the drop line (Pin left, Unpin and move here, Unpin: returns here, Reorder the pins) and dashes it where a pin returns. **ratatui:** the zones lit, the return line dashed and the drop's caption on the status line.
- **core:** saving and restoring a layout ([#154](https://github.com/flotilla-org/binnacle/issues/154)). `Grid::set_pins(axis, edge, keys)` makes an edge's pins those Keys in that order, dormant where the Table Source lacks them; `Effect::PinsChanged { axis, edge, keys }` reports each change to an edge's pins, from a pin, unpin, freeze or `set_pins`, one per edge in the queue; `Snapshot::pins(axis, edge)` lists them. `Grid::size_overrides(axis)` lists every Size Override, shown or not, in Key order. Mirrored as `binnacle_grid_set_pins`, `binnacle_grid_size_overrides` and the C axis snapshot's pin lists, and `WebGrid.set_pins`, `size_override_keys` and `size_override_sizes` in wasm.
- **web:** `GridWidget.layout()` and `restoreLayout(layout)`: the View Spec, pins, Size Overrides and Header Band thicknesses by the Table Source's IDs, versioned (`LAYOUT_VERSION`) and plain enough for `JSON.stringify`. Restoring sets pins, sizes and bands at once and asks for the View Spec as an ordinary request; it never fails on what the source lacks, and restores nothing of another version. The ID of a pinned or sized item the Table Source lacks is kept through Resets until it is unpinned or its size reset, so a later `layout()` still names it. A layout leaves out the widths the widget computed itself (`initialColumnWidth` and `initialRowHeight` fits and fills, while still what it set), and restoring keeps the other grid's own; fixed initial sizes and every width the user or app sets are saved. The demos' Save layout and Restore layout buttons keep one in the browser and restore it on load.
- **ratatui:** `save_layout(grid)` and `restore_layout(grid, layout)` do the same by Key, in a `SavedLayout`; the demo saves with Ctrl+S and restores with Ctrl+O.
- **core:** dormant pins and clipping ([#152](https://github.com/flotilla-org/binnacle/issues/152)). A pin whose item a `Refiltered` filtered out or hid goes dormant once `Locate` says it is gone, and returns in its place in pin order when the item comes back; until the answer it is drawn as it was. `Grid::set_min_scrolling(axis, length)` keeps a scrolling region: pinned Strips too long to leave it clip at their inside ends, the trailing one first, and nothing unpins. Focus on a clipped pinned item slides its Strip to show it, and the trailing Strip makes room for its focused item. `Snapshot::pinned_region(axis, edge)` says where each pinned Strip draws; selection fills are clipped to it. Mirrored as `binnacle_grid_set_min_scrolling` and the C axis snapshot's regions, and `WebGrid.set_min_scrolling` and the axis snapshot's `regions` in wasm.
- **ratatui:** `HeaderMenu` pins too ([#152](https://github.com/flotilla-org/binnacle/issues/152)), as the web's menu does: Pin left and Pin right (Pin top and Pin bottom for a row), or Unpin wherever the item is pinned, clipped or not, then Freeze up to here, on keys `l`, `r`, `t`, `b`, `u` and `f`, before Hide, Show only and Choose. It opens on any axis now, with the hiding lines only where the source hides, and its cursor starts on the first line.
- **web, ratatui:** pinned items draw clipped to their regions, with the pinned edge where a Strip clips. The web keeps 50 px of each axis to scroll.
- **core:** hiding ([#148](https://github.com/flotilla-org/binnacle/issues/148)): `Grid::hide(axis, keys)` and `Grid::show(axis, keys)` ask the Table Source for the View Spec in force with those items hidden or shown (`ViewEdit::Hide`, `ViewEdit::Show`), on an axis whose source declares it (`set_hide_support`). The answer is a `Refiltered`, so focus, the selection and picks follow its rules, while Size Overrides stay for when the items come back. `Snapshot::hide_support` and `Snapshot::hidden`.
- **memory:** the In-Memory Table Source hides items on either axis apart from the filter (`apply_hidden`, `hidden`, `is_hidden`), pruning Keys the data lacks; `MemorySource` applies a View Spec's hidden Keys, and its quick filters searching the shown items skip hidden ones, as do its distinct values. `PumpSource::hide_support`.
- **C API:** `binnacle_grid_set_hide_support`, `binnacle_grid_hide` and `binnacle_grid_show`; `BinnacleAxisView` and `BinnacleAxisSnapshot` carry the hidden Keys, and the Snapshot each axis's hide support.
- **web:** `grid.hide`, `grid.show`, `grid.hidden` and `grid.canHide`; an axis's `hide` flag; `fromRows` hides both axes. The column and row menus gain "Hide column" and "Show hidden columns ▸" (a flyout with a search past eight items). Keys: Mod+Alt+0 and Mod+Alt+9 hide the focused column and row, with Shift they list the hidden ones, and Shift+F10 or the context menu key opens the column menu. A key binding naming a letter or digit now also matches with Option on macOS, which changes the key reported. `FrameInfo` axes count their hidden items.
- **core:** a hide cap per axis ([#149](https://github.com/flotilla-org/binnacle/issues/149)): 1,000 hidden items (`HIDE_CAP`), or fewer where the Table Source declares it (`Grid::set_hide_cap`, `PumpSource::hide_cap`); `Snapshot::hide_cap`. The C API mirrors it with `binnacle_grid_set_hide_cap`, `BinnacleAxisSnapshot.hide_cap` and `binnacle_grid_hide` returning `BINNACLE_HIDE_CAPPED`; wasm with `set_hide_cap`, `hide` returning `false`, and the axis's `hideCap`.
- **ratatui:** the chooser (`Chooser`): a checklist of an axis's items with a search, shown items in source order then hidden ones, each tick hiding or showing at once, "(Show all)" at its head. `Control::Chooser` (Chords Alt+O, Alt+Shift+C or Alt+Shift+O for the rows; Modes `C` and Alt+C; BareKeys `c` and `C`) and the menu's "Choose…" open it. `HeaderMenu` gains "Show only this" and counts the chosen items ("Hide 3 columns"); `hide_chosen`, `show_only_chosen`, `Chosen`, `Hid` and `cap_hint` ("Can't hide over 100 rows: filter"). The demo caps the records at 100.
- **web:** `createChooser(widget)`, the same chooser, opened by Mod+Alt+O (Mod+Alt+Shift+O for the rows), the menus' "Choose columns…" or `chooser.open`. `GridWidget.hideChosen`, `showOnly`, `chosenCount`, `items`, `hideCap`, `attachChooser`, `canChoose` and `openChooser`; the menus' "Hide 3 columns" and "Show only these 3 columns"; an axis's `hideCap` and `fromRows`'s `hideCap` option; the filter bar shows the cap's hint. `capHint` and `HideOutcome`.
- **ratatui:** `Control::Hide`, `Control::ShowHidden` and `Control::Menu`, bound in every preset (Chords: Alt+0 and Alt+9 hide the focused column and row, Alt+) and Alt+( list the hidden ones, Alt+M or Shift+F10 opens the column menu, Alt+Shift+M the row menu; Modes and BareKeys: `-`, `_`, `+`, `*`, `.` and `,`). `hide_focused` hides the focused item, and `HeaderMenu` is the column or row menu: Hide, then the hidden items numbered, then Show all. The demo shows them, transposed too.

- **memory:** `Transposed`, a Table Source on its side: the Grid's rows are the inner source's columns and its columns the inner source's rows. With it a row-major source, such as the In-Memory Table Source over records, serves a column-major table. `transpose_spec`, `transpose_totals`, `transpose_find` and `transpose_match` turn the values that cross it.
- **web:** `transpose(source)`, the same for a web Table Source, so `transpose(fromRows(...))` shows each record as a column.
- **testkit:** `ColumnMajorTable`, the records of a `RecordTable` on their side, for scenarios and properties.
- **core:** pinning. `Grid::pin(axis, edge, key)` pins an item's Key to the leading edge of its axis and `Grid::unpin(axis, key)` unpins it: pinned items draw in a pinned Strip of their own after the Header Band, in pin order, whatever the sort or scroll, and the scrolling Strip skips them. Pins follow their Keys through sorts and filters. `Snapshot::pinned(axis, edge)`, `scrolling(axis)` and `drawn(axis)` describe the Strips; hit-testing and resizing reach pinned items. The C API mirrors it with `binnacle_grid_pin` and `binnacle_grid_unpin`, the wasm bridge with `WebGrid.pin` and `unpin`.
- **ratatui:** the pinned edge, `║` in the Gap after the pinned columns in every Border Style, capped `╥` at the band rule and `╨` at the closing rule (`┃`, `┰`, `┸` under Double). `Control::Pin` and `Control::Unpin` in every preset (chords Alt+, and Alt+U, modes `!` and Alt+U, bare keys `<` and `u`), carried out by `toggle_pin` and `unpin_focused`.
- **web:** the pinned edge, a line in the `pinnedEdge` Theme role (the border colour by default) with a `pinnedShadow` once the body has scrolled under it. `GridWidget.pin`, `unpin` and `pinned`; the column menu's "Pin left" and "Unpin"; Alt+Shift+ArrowLeft pins the focused column (or unpins it) and Alt+Shift+Backspace unpins it. ARIA reads cells in Position order across the Strips.
- **core:** pins at the trailing edge and on rows: `Grid::pin(axis, Edge::Trailing, key)` draws an item in a trailing pinned Strip, in pin order, ending flush with the viewport's far end. `Grid::freeze(axis, key)` ("freeze up to here") pins every item from the start up to `key` in their current order, as many as fit with room left to scroll; on a leading pin it unpins those after it. `Grid::set_edge_gap(axis, gap)` sets the least space between a pinned Strip and the scrolling one, where adapters draw the edge. Mirrored as `binnacle_grid_freeze`, `binnacle_grid_set_edge_gap` and `BINNACLE_EDGE_TRAILING` in the C API and `WebGrid.freeze`, `set_edge_gap` and edge code 1 in wasm.
- **ratatui:** the trailing edge (`║` before the right pinned columns) and row edges, a `═` rule after the top pinned rows and before the bottom ones (`━` under Double), capped `╞` and `╡` and crossing column lines with `╪` and column edges with `╬`. Controls `Pin` right, top and bottom, `Unpin` rows and `Freeze` either axis: chords Alt+., Alt+<, Alt+>, Alt+Shift+U, Alt+W and Alt+Shift+W; modes `>`, `[`, `]`, Alt+Shift+U, `z` and `Z`; bare keys `>`, `[`, `]`, `U`, `z` and `Z`; `freeze_focused` carries out `Freeze`.
- **web:** trailing pinned Strips and pinned rows, each with its edge and a shadow on the scrolling side. `GridWidget.pin(axis, id, "trailing")`, `freeze(axis, id)`; the column menu's "Pin right" and "Freeze up to here", the row menu's "Pin top", "Pin bottom" and "Freeze up to here"; Alt+Shift+ArrowRight, ArrowUp and ArrowDown pin the focused column right or its row to the top or bottom, Mod+Alt+Shift+Backspace unpins the row, and Alt+Shift+Home (Mod+Alt+Shift+Home) freezes the columns (rows) up to focus.
- **demos:** a column-major source in both demos: `binnacle-demo --transposed` and the web demo's `transposed` source.
- **memory:** `MemorySource` sorts its columns by rows' values (integers, numbers or text, whichever every column with a sort closure gives), re-sorts them when such a row changes, and drops rows that left on a replace from the columns' sort. `InMemoryTableSource::base_len` and `base_key`.
- **web:** `fromRows` sorts the columns by rows' values the same way; the `headerClick` option sets what a header click does per axis (`"sort"`, `"select"` or `"none"`), as the C API's `binnacle_grid_set_header_click` does; row headers show the columns' sort marker and pending shimmer, and carry `aria-sort`; the live region says "Columns sorted by …". Fitting the row header band leaves room for a sort marker.
- **ratatui:** row headers show the columns' sort marker (`▲`, `▼`, the place, `~`) and the pending shimmer; `animating` counts them.
- **demos:** in the transposed demos a click on a field's row header sorts the records by it.
- **core:** `SelectionUnit::Cols` (a click or focus move selects the cell's whole column) and `Action::SelectRow` (every column of the range's rows, or of the focused row), beside `SelectColumn`. The C API mirrors them as `BINNACLE_SELECT_COLS` and `binnacle_grid_select_row`, wasm as unit code 2 and `select_row`.
- **ratatui:** the headers of selected rows and columns are highlighted (`Theme::header_selected`); Shift+Space selects the row and Alt+PageUp and Alt+PageDown page the columns; `Keymap::preset(preset)` binds what each preset adds (`V` selects the row in modes and bare keys, `h j k l` move in modes) and `Keymap::keys(action)` lists an Action's keys.
- **web:** the `"cols"` selection unit, a `SelectRow` Action on Shift+Space, Alt+PageUp and Alt+PageDown page the columns, and picked columns are marked under their headers and in their cells. The row header band widens once, on the first rows, to fit their labels (and a sort marker where row headers sort), so a column-major table shows its field names whole.
- **demos:** both demos count picked rows and columns; the ratatui demo's Alt+S switches the selection unit.
- **memory, web:** the In-Memory Table Source (`MemorySource`) and `fromRows` filter their columns by the rows' values: the quick filter, conditions, a row's distinct values and unmatched columns. A change from the data moves only the columns whose match changed (`refilter_items`).
- **ratatui:** `ColumnFilter::open_row` (Alt+Right in Chords) filters the columns by a row's values; `render_conditions` adds "Columns where" chips, `count(snapshot, axis, nouns)` counts either axis, and `QuickFilter::on(Axis::Cols)` filters the columns.
- **web:** the column menu is the row menu too (`attachRowMenu`, `openRowMenu`, Alt+ArrowRight, `menu.openRow`); the widget's filter methods and `distinct` take an axis; `rowSupport`, `rowLabel` and `FrameInfo.columnsFilter`; the filter bar shows the columns' chips and count, with `nouns` and `axis` options.
- **core:** moves on either axis. `Grid::set_movable` says whether the Table Source can move an axis's items now (withdrawing it ends a drag on that axis), `Grid::move_answered` answers a `MoveRequested` with `None` or a refusal's reason; the Snapshot gives `movable(axis)`, `pending_move()`, `move_refusal()` (until the next press) and `HeaderPlacement::move_pending`. The C API mirrors them (`binnacle_grid_set_movable`, `binnacle_grid_move_answered`, `BINNACLE_HEADER_MOVE_PENDING`, the axis's `movable`, the snapshot's pending move and refusal) and now carries `BINNACLE_EFFECT_MOVE_REQUESTED`; wasm mirrors them too.
- **memory:** the In-Memory Table Source moves rows as it moves columns. A move's drop Position is read in the filtered order. On a sorted axis `MovePolicy::Bake` (the default) keeps the order shown, places the items and clears the axis's sort, which `MemorySource` reports with the View Spec it leaves; `MovePolicy::Refuse` refuses and makes the axis not movable while sorted. `Moved`, `answer_move`, `InMemoryTableSource::movable`, `set_move_policy`, `MemorySource::with_move_policy`.
- **web:** row headers drag to move rows. `move` may answer `{ refused: reason }`, which shows near the headers where it was dropped and is announced; `movable()` and the sink's `movableChanged()` say whether an axis can move now. Moved headers shimmer until the answer. `fromRows` moves either axis, and its `sortedMoves` option (`"bake"` or `"refuse"`) says what a move on a sorted axis does.
- **ratatui:** moved headers shimmer until the move is answered (`animating` counts them), a row drop line underlines the row above when there is no row Gap, and the status line says why a move was refused, or that one waits for its answer.
- **demos:** both demos move records and fields by their headers, upright and transposed; `binnacle-demo --refuse-sorted-moves` and the web demo's `?sortedMoves=refuse` refuse moves while sorted. The huge demos offer no moves.
