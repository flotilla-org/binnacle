# Rows that fit their content: prior art

How do established grids and table viewers give rows (and header lines) heights that follow their content, under virtualization, and what can binnacle borrow? This note answers the research ticket [#274](https://github.com/flotilla-org/binnacle/issues/274) for the map [Long values (#273)](https://github.com/flotilla-org/binnacle/issues/273), and feeds the grilling tickets on [rows that size to their content (#275)](https://github.com/flotilla-org/binnacle/issues/275), [where wrap lives (#276)](https://github.com/flotilla-org/binnacle/issues/276), [expanding a cut cell (#277)](https://github.com/flotilla-org/binnacle/issues/277) and [tooltips (#278)](https://github.com/flotilla-org/binnacle/issues/278). It surveys AG Grid, MUI X, Glide Data Grid, TanStack Virtual, RevoGrid, SlickGrid, and the terminal tools VisiData, csvlens, tabiew and ratatui's `Table`.

Terms follow [`CONTEXT.md`](https://github.com/flotilla-org/binnacle/blob/main/CONTEXT.md). binnacle was read at `main` `191f1a4`.

Numbering: `docs/research/` on main holds 01, 02 and 06; the research branches hold 03 to 05 and 07 to 09. 10 is the next free number, as the ticket asked.

## Summary

- **Three ways to get a content height.** *The grid measures the DOM after render* (AG Grid per cell, MUI X per row, TanStack Virtual per item, all with a `ResizeObserver`). *The host computes the height up front* from data (Glide's `rowHeight` callback, SlickGrid's `rowHeightProvider`, RevoGrid's `rowDefinitions`, ratatui's `Row::height`). *The viewer wraps text itself each frame* for the rows on screen (csvlens, VisiData). No canvas grid measures for the host: Glide's feature request for it was closed without one.
- **Unmeasured rows are estimated at one default size** almost everywhere. MUI X alone takes a per-row estimate (`getEstimatedRowHeight`); TanStack Virtual's docs advise estimating the largest likely size. Heights already measured are cached by row id or key after the row scrolls away (AG Grid, MUI X, TanStack Virtual).
- **Scrolling up into newly measured rows is the hard case, and most grids accept the jump.** AG Grid's docs say outright "It is not possible to avoid these effects". MUI X turns off the browser's scroll anchoring and does not compensate. TanStack Virtual is the exception: it adjusts `scrollTop` when an item above the viewport changes size, except while the user scrolls backward, and its issue history ([#659](https://github.com/TanStack/virtual/issues/659), [#1227](https://github.com/TanStack/virtual/issues/1227)) shows what it took. A scroll position held as an item plus an offset into it, as binnacle's Scroll Anchor is, avoids the problem by construction.
- **Scroll to row N needs a settle loop once heights are lazy.** AG Grid's `ensureIndexVisible` retries up to 10 times while measured heights move the target; TanStack Virtual's `scrollToIndex` reconciles on each animation frame until the offset is stable for a few frames, giving up after 5 s. MUI X scrolls once against estimates.
- **The scrollbar thumb drifts and everyone documents it** (AG Grid, MUI X, TanStack Virtual's `getTotalSize`). No product reserves or smooths it.
- **Measuring costs column virtualization in the DOM grids.** AG Grid always renders `autoHeight` columns; MUI X turns column virtualization off for a page with an auto-height row unless `virtualizeColumnsWithAutoRowHeight` is set, at which point "row height might change during horizontal scrolling". Terminal viewers wrap only the cells on screen.
- **Line clamps are rare.** VisiData has one (`disp_wrap_max_lines=3`, ending in `disp_wrap_placeholder='…'`), plus a per-column fixed height and a focus mode where only the cursor row grows. No web grid ships a clamp; Glide clips wrapped text at the cell edge with no marker; MUI X documents a "view more" recipe.
- **Header wrap is uncommon.** AG Grid has `wrapHeaderText` and `autoHeaderHeight` on columns and column groups, each header row taking its tallest cell. SlickGrid measures one common header height. MUI X, Glide, csvlens and tabiew keep one fixed line; VisiData and ratatui allow explicit newlines only.
- **Expanding a cut cell has four shapes.** A tooltip shown only when the text overflows (AG Grid `tooltipShowMode: 'whenTruncated'`, MUI X header titles, SlickGrid AutoTooltips); a popover over the cell (MUI X's `GridCellExpand` recipe, Glide's read-only overlay); a side pane or a sheet of the row (tabiew, VisiData `Enter`); growing in place (VisiData `v`, csvlens `-S`/`-W`). csvlens [issue 83](https://github.com/YS-L/csvlens/issues/83), which asks for a popup, is still open: the follow-up that shipped was the `--wrap` flag.
- **Keyboard routes are thin.** AG Grid shows tooltips on focus (`tooltipTrigger: 'focus'`); Glide opens its overlay on Space or Enter; terminal viewers have keys for everything. MUI X's expand recipe has no keyboard route at all.
- **Tooltips are not always the value.** AG Grid's `tooltipField` and `tooltipValueGetter` show any text; MUI X's header tooltip shows the column's `description` instead of the full title when one is set.

## AG Grid

**Who measures, when, with what.** Two routes.
- *`autoHeight` columns:* the grid measures each rendered cell's wrapper (`offsetHeight` plus padding and border) at setup and on every `ResizeObserver` callback, retrying up to 5 times on `setTimeout(0)` while the element is detached or reads 0 ([`rowAutoHeightService.ts` L198-L252](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/rendering/row/rowAutoHeightService.ts#L198-L252)). Heights are stored per column on the row node; a 1 ms debounced pass sets the row to its tallest cell, never below the configured height, then calls `onRowHeightChanged` (same file L42-L79, L168-L189). A row that leaves the view keeps its last height in `__autoContentHeight` (L57-L63, L115-L133). The docs: the grid listens "for height changes for all Cells configured for Auto Height… only looking at rows that are currently rendered" ([row height docs L151-L155](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/documentation/ag-grid-docs/src/content/docs/row-height/index.mdoc#L151-L155)).
- *`getRowHeight` callback:* the host answers. When the grid can scroll, rows first get the default height flagged `estimated` ([`gridOptionsUtils.ts` L145-L157](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/gridOptionsUtils.ts#L145-L157), [`clientSideRowModel.ts` L442-L464](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/clientSideRowModel/clientSideRowModel.ts#L442-L464)); `ensureRowHeightsValid` then calls the real callback for rows in the viewport only, looping until positions settle (same file L286-L321). The grid asks once per row; `resetRowHeights()` clears and asks again, and `rowNode.setRowHeight()` plus `onRowHeightChanged()` set heights by hand ([row height docs L50-L81](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/documentation/ag-grid-docs/src/content/docs/row-height/index.mdoc#L50-L81)). Variable heights do not work with the Viewport or Infinite row models (L8-L11).

**Estimates and scroll stability.** The estimate is the default row height (theme, or `rowHeight`). The docs are blunt: the scroll thumb "will either lag behind or jump ahead", and when scrolling up into rows shown for the first time "the row positions will jump… It is not possible to avoid these effects" ([L157-L163](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/documentation/ag-grid-docs/src/content/docs/row-height/index.mdoc#L157-L163)). No anchoring compensation was found (*inferred*). `ensureIndexVisible` loops up to 10 times while the target's top or height moves "due to lazy calculation of row heights", and retries on `modelUpdated` up to 10 times more, cancelling if the user scrolls ([`gridBodyScrollFeature.ts` L597-L720](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/gridBodyComp/gridBodyScrollFeature.ts#L597-L720)). Related threads: [#7273](https://github.com/ag-grid/ag-grid/issues/7273) (`ensureNodeVisible` with `autoHeight`), [#3105](https://github.com/ag-grid/ag-grid/issues/3105) (jumps after `resetRowHeights`), [#4883](https://github.com/ag-grid/ag-grid/issues/4883).

**Re-measure and cost.** The observer is on the cell, so a column resize, a content change or a font reflow re-measures any rendered cell (*inferred*); measuring pauses while a cell is edited (`rowAutoHeightService.ts` L208). `autoHeight` columns "will always be rendered… adds size listeners to cells and stops Column Virtualisation for these columns" ([L147-L149](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/documentation/ag-grid-docs/src/content/docs/row-height/index.mdoc#L147-L149); [`columnViewportService.ts` L151-L155](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/columns/columnViewportService.ts#L151-L155)). A user hit this on 50 rows by 70 columns ([#7408](https://github.com/ag-grid/ag-grid/issues/7408)).

**Clamp.** None. `wrapText` is CSS `white-space: normal` ([L101-L117](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/documentation/ag-grid-docs/src/content/docs/row-height/index.mdoc#L101-L117)); unwrapped cells end in an ellipsis.

**Headers.** `wrapHeaderText` and `autoHeaderHeight` sit on `AbstractColDef`, so column groups have them too ([`colDef.ts` L121-L127](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/entities/colDef.ts#L121-L127); [`agColumnGroup.ts` L295-L297](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/entities/agColumnGroup.ts#L295-L297)). Header cells are measured like body cells ([`abstractHeaderCellCtrl.ts` L235-L290](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/headerRendering/cells/abstractCell/abstractHeaderCellCtrl.ts#L235-L290)), and each header row is the tallest of its default (`headerHeight`, `groupHeaderHeight`, pivot variants) and its auto-height cells ([`headerUtils.ts` L87-L112](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/headerRendering/headerUtils.ts#L87-L112)). Columns with an auto-height header are kept rendered outside the viewport so the row height stays right ([`columnViewportService.ts` L115-L127](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/columns/columnViewportService.ts#L115-L127)).

**Expanding and tooltips.** `tooltipShowMode: 'whenTruncated'` shows a tooltip only when the element overflows (`scrollWidth > clientWidth` or the same vertically) ([`dom.ts` L325-L344](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-stack/src/utils/dom.ts#L325-L344); [`cellTooltip.ts` L40-L70](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/tooltip/cellTooltip.ts#L40-L70)). `tooltip: true` shows the value, but `tooltipField` and `tooltipValueGetter` show any text ([tooltip docs L9-L28](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/documentation/ag-grid-docs/src/content/docs/tooltips/index.mdoc#L9-L28)). `tooltipTrigger: 'focus'` shows tooltips on cell or header focus, with no delay ([`gridOptions.ts` L287-L295](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/entities/gridOptions.ts#L287-L295)); with `tooltipInteraction`, Tab enters the tooltip and Escape closes it (tooltip docs L125-L141). For long text the only expander is an editor: `agLargeTextCellEditor` as a popup textarea, opened with Enter or F2 ([`largeTextCellEditor.ts` L37-L48](https://github.com/ag-grid/ag-grid/blob/d89378d03f33322b443219fc45b78f8db0268f3d/packages/ag-grid-community/src/edit/cellEditors/largeTextCellEditor.ts#L37-L48)). No read-only expander was found (*inferred*).

## MUI X Data Grid

**Who measures, when, with what.** The grid, per **row**: one shared `ResizeObserver` on row elements reads `borderBoxSize.blockSize` and stores it by row id, scheduling `hydrateRowsMeta` in an animation frame when stored positions go stale ([`dimensions.ts` L666-L701](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-virtualizer/src/features/dimensions.ts#L666-L701)). Rows whose `getRowHeight` returns `'auto'` register themselves ([`GridRow.tsx` L164-L178](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-data-grid/src/components/GridRow.tsx#L164-L178)) and their cells switch to `white-space: initial` ([`GridRootStyles.ts` L623-L626](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-data-grid/src/components/containers/GridRootStyles.ts#L623-L626)). "Rows are measured as they are rendered" ([row height docs L51-L56](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/docs/data/data-grid/row-height/row-height.md#L51-L56)).

**Estimates and scroll stability.** Unmeasured rows use `getEstimatedRowHeight(row)` if given, else the base height (52) ([`dimensions.ts` L520-L555](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-virtualizer/src/features/dimensions.ts#L520-L555)). `hydrateRowsMeta` rebuilds cumulative positions over every row on the page (L581-L628); offset to row is a binary search over measured positions, exponential past the last measured one ([`virtualization.ts` L1091-L1122](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-virtualizer/src/features/virtualization/virtualization.ts#L1091-L1122)). Measured heights outlive unmounting and are pruned only when a row leaves the tree ([`useGridRowsMeta.ts` L88-L98](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-data-grid/src/hooks/features/rows/useGridRowsMeta.ts#L88-L98)). The docs warn of "the scrollbar thumb changing during scroll" (row height docs L51-L53). The scroller sets `overflow-anchor: none` ([`GridRootStyles.ts` L197-L199](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-data-grid/src/components/containers/GridRootStyles.ts#L197-L199)) and the grid does not compensate `scrollTop` (*inferred*). `scrollToIndexes` is one shot against current positions ([`useGridScroll.ts` L63-L145](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-data-grid/src/hooks/features/scroll/useGridScroll.ts#L63-L145)). Threads: [#14726](https://github.com/mui/mui-x/issues/14726) (glitch, fixed by ignoring a 0 px reading for a focused virtual row), [#16813](https://github.com/mui/mui-x/issues/16813) (rows move after scroll, open), [#7817](https://github.com/mui/mui-x/issues/7817) (rows do not shrink when a column widens, open).

**Re-measure and cost.** Any change to the row's box (*inferred* from the observer), plus a layout-effect rehydrate on data changes ([`dimensions.ts` L704-L707](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-virtualizer/src/features/dimensions.ts#L704-L707)); `resetRowHeights()` clears the cache. Column virtualization is off while a rendered row has auto height ([`virtualization.ts` L1058-L1065](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-virtualizer/src/features/virtualization/virtualization.ts#L1058-L1065)) unless `virtualizeColumnsWithAutoRowHeight`, which warns the height may change while scrolling sideways ([row height docs L80-L89](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/docs/data/data-grid/row-height/row-height.md#L80-L89)).

**Clamp.** None built in; cells are `nowrap` with an ellipsis ([`GridRootStyles.ts` L571-L583](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-data-grid/src/components/containers/GridRootStyles.ts#L571-L583)). The `ExpandableCells` demo cuts at 200 characters with a "view more / view less" button whose state lives in the cell and is lost when it unmounts ([`ExpandableCells.tsx` L26-L44](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/docs/data/data-grid/row-height/ExpandableCells.tsx#L26-L44)).

**Headers.** Fixed `columnHeaderHeight` (56) and `columnGroupHeaderHeight` ([column groups docs L60-L66](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/docs/data/data-grid/column-groups/column-groups.md#L60-L66)). No wrap; the title ellipsises and shows a tooltip with the full title only when it overflows, or the column's `description` instead when set ([`GridColumnHeaderTitle.tsx` L25-L87](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/packages/x-data-grid/src/components/columnHeaders/GridColumnHeaderTitle.tsx#L25-L87)). **Expanding.** The `GridCellExpand` recipe, not an API: on mouse enter it checks for overflow and opens a Popper at the cell's width with the full value; Escape or mouse leave closes it, and there is no keyboard way in ([`RenderExpandCellGrid.tsx` L13-L108](https://github.com/mui/mui-x/blob/470d1daa310b55ce050fc7e46d75d4dd0a61b39b/docs/data/data-grid/column-definition/RenderExpandCellGrid.tsx#L13-L108)). **Wrap and clamp.** `allowWrapping` splits text and stops drawing at the cell's bottom edge, with no ellipsis or other marker ([`data-grid-lib.ts` L509-L547](https://github.com/glideapps/glide-data-grid/blob/0875d78cc41535a39f8b417ff88ce1ebe129c363/packages/core/src/internal/data-grid/render/data-grid-lib.ts#L509-L547)). **Headers.** Fixed `headerHeight` and `groupHeaderHeight`; titles are one `fillText` with a fade under the menu ([`data-grid-render.header.ts` L493-L522](https://github.com/glideapps/glide-data-grid/blob/0875d78cc41535a39f8b417ff88ce1ebe129c363/packages/core/src/internal/data-grid/render/data-grid-render.header.ts#L493-L522)).

**Expanding and tooltips.** The overlay editor is the expander: at least the cell's size, at most 400 px wide, limited to the viewport height with its own scroll ([`data-grid-overlay-editor-style.tsx` L10-L60](https://github.com/glideapps/glide-data-grid/blob/0875d78cc41535a39f8b417ff88ce1ebe129c363/packages/core/src/internal/data-grid-overlay-editor/data-grid-overlay-editor-style.tsx#L10-L60)). Space, Enter and Shift+Enter open it ([`data-editor-keybindings.ts` L133](https://github.com/glideapps/glide-data-grid/blob/0875d78cc41535a39f8b417ff88ce1ebe129c363/packages/core/src/data-editor/data-editor-keybindings.ts#L133)). ## TanStack Virtual (headless)

**Who measures.** The host attaches `measureElement` as a ref; one shared `ResizeObserver` reads `borderBoxSize`, batching all entries before one notify ([`index.ts` L262-L306, L643-L717, L1935-L1974](https://github.com/TanStack/virtual/blob/18d08351cfd969224fb7353832897cc600b21c30/packages/virtual-core/src/index.ts#L1935-L1974)).

**Estimates and cache.** Measured sizes live in a `Map` by item key; others use `estimateSize(i)` ([L488](https://github.com/TanStack/virtual/blob/18d08351cfd969224fb7353832897cc600b21c30/packages/virtual-core/src/index.ts#L488)). Positions are a prefix sum rebuilt from the lowest changed index, so a batch costs O(n - min) ([L1600-L1705](https://github.com/TanStack/virtual/blob/18d08351cfd969224fb7353832897cc600b21c30/packages/virtual-core/src/index.ts#L1600-L1705)); offset to item is a binary search. `getTotalSize` is the last item's end, so the scrollbar drifts as estimates are replaced ([L2532-L2545](https://github.com/TanStack/virtual/blob/18d08351cfd969224fb7353832897cc600b21c30/packages/virtual-core/src/index.ts#L2532-L2545)); the docs advise estimating the largest likely size ([`virtualizer.md` L31-L39](https://github.com/TanStack/virtual/blob/18d08351cfd969224fb7353832897cc600b21c30/docs/api/virtualizer.md#L31-L39)). `initialMeasurementsCache` restores a `takeSnapshot()` so a remounted list keeps its scroll (L318-L326).

**Anchoring, the one product that does it.** In `resizeItem`, an item's first measurement is compensated in `scrollTop` if the item starts above the scroll offset; a later re-measurement is compensated only if the item is wholly above the viewport and the user is not scrolling backward, which stops the cascade when scrolling up ([L1976-L2097](https://github.com/TanStack/virtual/blob/18d08351cfd969224fb7353832897cc600b21c30/packages/virtual-core/src/index.ts#L1976-L2097)). The write and the re-render land in one paint. The rule is overridable through `shouldAdjustScrollPositionOnItemSizeChange` (L630-L636). The road there: [#659](https://github.com/TanStack/virtual/issues/659) "Scrolling up with dynamic heights stutters and jumps", [#1227](https://github.com/TanStack/virtual/issues/1227), and [#981](https://github.com/TanStack/virtual/issues/981) still open for Lit.

**Scroll to index.** It scrolls to an offset computed from estimates, then an animation-frame `reconcileScroll` loop recomputes the target as measurements arrive, retiring after 2 or 3 stable frames or 5 s ([L1420-L1520, L2374-L2387](https://github.com/TanStack/virtual/blob/18d08351cfd969224fb7353832897cc600b21c30/packages/virtual-core/src/index.ts#L1420-L1520)). Earlier failures: [#468](https://github.com/TanStack/virtual/issues/468), [#541](https://github.com/TanStack/virtual/issues/541) (worse scrolling up), [#1290](https://github.com/TanStack/virtual/issues/1290).

**Re-measure.** Any observed size change, or `measure()`, which clears the whole cache ([L2672-L2681](https://github.com/TanStack/virtual/blob/18d08351cfd969224fb7353832897cc600b21c30/packages/virtual-core/src/index.ts#L2672-L2681)). Clamps, headers and expansion are the host's.

## RevoGrid and SlickGrid

**RevoGrid: a default plus sparse overrides, sizes known up front.** `rowSize` is the default; `rowDefinitions` and drag resizes add per-row sizes ([`revo-grid.tsx` L150-L206](https://github.com/revolist/revogrid/blob/bce0c9aff2aeef1b9dd801ba9b2cb0588aea7542/src/components/revoGrid/revo-grid.tsx#L150-L206)). Only changed sizes are kept, sorted with their start positions, so position to row is a binary search over overrides plus arithmetic ([`dimension.helpers.ts` L26-L143](https://github.com/revolist/revogrid/blob/bce0c9aff2aeef1b9dd801ba9b2cb0588aea7542/src/store/dimension/dimension.helpers.ts#L26-L143)). Measuring exists only for columns (`autoSizeColumn`, "not performance efficient", in a hidden DOM div); row auto-size is a paid Pro feature ([rv-grid.com/pro](https://rv-grid.com/pro/)). Header wrap is CSS the user adds ([#271](https://github.com/revolist/revogrid/issues/271)).

**SlickGrid: opt-in variable heights from a host provider.** Long fixed ("you can only set the row height once", [#476](https://github.com/6pac/SlickGrid/issues/476)), it gained `enableVariableRowHeight` in v5.19.0, opt-in "for perf reasons". Heights come from `rowHeightProvider(grid, row, item)`, which must be "a simple lookup or calculation, no DOM access" ([`gridOption.interface.ts` L200-L208, L328-L340](https://github.com/6pac/SlickGrid/blob/876deb20ece575d6b8c8458cc859b726a5168637/src/models/gridOption.interface.ts#L328-L340)), stored in a `Float64Array` prefix sum rebuilt on count changes or `invalidateRowHeights()` ([`slick.core.ts` L1362-L1460](https://github.com/6pac/SlickGrid/blob/876deb20ece575d6b8c8458cc859b726a5168637/src/slick.core.ts#L1362-L1460)). `autoHeaderHeight` measures the rendered headers and applies one common height ([`slick.grid.ts` L2020-L2050](https://github.com/6pac/SlickGrid/blob/876deb20ece575d6b8c8458cc859b726a5168637/src/slick.grid.ts#L2020-L2050)). The AutoTooltips plugin sets `title` only when `clientWidth < scrollWidth` ([`slick.autotooltips.ts` L72-L81](https://github.com/6pac/SlickGrid/blob/876deb20ece575d6b8c8458cc859b726a5168637/src/plugins/slick.autotooltips.ts#L72-L81)).

## VisiData

**Multi-line rows, by a per-column height, not by content.** `Column.height` is a maximum ([`column.py` L78](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/column.py#L78)); a row's height is the largest over visible columns, cached for one frame ([`sheets.py` L400-L403](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/sheets.py#L400-L403)). `v` toggles visible columns between 1 and `default_height` (4); `zv` asks for N; `gzv` fits the cursor row, capped at the window ([`layout.py` L44-L96](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/features/layout.py#L44-L96)). `drawRow` pads or cuts every cell to the height, so expanded rows are all the same height ([`sheets.py` L1044-L1047](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/sheets.py#L1044-L1047)). By default (`disp_multiline_focus`) only the cursor row expands ([L996-L1000](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/sheets.py#L996-L1000)). `zj` and `zk` scroll a cell's lines.

**Wrapping, clamp, marker.** Wrapping runs each frame for drawn rows and visible cells, at display width with `wcwidth` when installed and character count otherwise ([`cliptext.py` L11-L15](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/cliptext.py#L11-L15)), cached by width ([`sheets.py` L27-L43](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/sheets.py#L27-L43)). `disp_wrap_max_lines=3` and `disp_wrap_placeholder='…'` clamp a cell; `color_multiline_bottom` marks a tall row's last line ([L18-L21, L1006-L1015](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/sheets.py#L1006-L1015)); a horizontal cut ends in `disp_truncator='…'`.

**Scrolling.** Whole rows only; a page is `n // rowHeight` rows, or `n - rowHeight + 1` in focus mode ([`sheets.py` L433-L439](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/sheets.py#L433-L439)); a row taller than the space left is cut ([L897](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/sheets.py#L897)). The docs say multi-line rows "can't be paged" ([`rows.md` L151-L158](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/docs/rows.md#L151-L158)).

**Headers.** Height is the most `\n`-separated lines in any column name; names are split, not wrapped ([`sheets.py` L441-L444](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/sheets.py#L441-L444)).

**Seeing a full value.** `Enter` pushes a sheet of the row, one line per column with editable values ([`pyobj.py` L232-L248, L315](https://github.com/saulpw/visidata/blob/02c7434ec3ee11b4a8f646c4200a574aae62f819/visidata/pyobj.py#L232-L248)); `e` scrolls a cell inline and `Ctrl+O` opens `$EDITOR`; `_` widens a column to fit. No tooltips.

## What binnacle can borrow

binnacle already has the shape the web grids reach for late. `AxisMeasure` keeps a default size, Size Overrides by Key and content sizes for the Window only ([`measure.rs` L23-L38](https://github.com/flotilla-org/binnacle/blob/191f1a4/crates/binnacle-core/src/measure.rs#L23-L38)); a Size Override wins over a content size, and every size outside the Window is the default ([`grid.rs` L332-L351](https://github.com/flotilla-org/binnacle/blob/191f1a4/crates/binnacle-core/src/grid.rs#L332-L351)). The Scroll Anchor is a Position plus an offset into it, and the thumb is estimated with sizes outside the Window taken as default ([`axis.rs` L546-L568](https://github.com/flotilla-org/binnacle/blob/191f1a4/crates/binnacle-core/src/axis.rs#L546-L568)). `set_window_sized` is reachable from the C API but no adapter calls it yet. These are recommendations for the grilling tickets, not decisions.

### For rows that size to their content (#275)

- **Who measures: keep the host or adapter measuring, as Glide, SlickGrid and the Grid's own auto-size Effects already do.** The DOM grids measure because the browser lays out their cells; binnacle's web adapter draws on canvas and ratatui wraps text itself, so both are in the Glide and csvlens position: the adapter wraps the Window's visible text and knows the line count. SlickGrid's rule ("a simple lookup or calculation, no DOM access") is a fair contract for the measuring call. `set_window_sized` fits this if the party that fills the Window can measure; where the Table Source fills the Window and the adapter measures, the core needs a second entry point that sets content sizes for Keys already in the Window without refilling it. That is the gap AG Grid's `setRowHeight` plus `onRowHeightChanged` and TanStack's `resizeItem` fill.
- **Estimates: default size, with an optional estimator later.** Every product starts at one default, MUI X adds a per-row estimate, and TanStack advises the largest likely size. binnacle could keep the axis default as the estimate and consider a host-given average or "typical wrapped height" later; per-row estimates cost a call per row and binnacle never sees rows outside the Window.
- **Remember measured sizes by Key, bounded.** AG Grid, MUI X and TanStack all keep heights after a row scrolls away, which is what stops a row coming back into view from being estimated again and jumping. binnacle drops content sizes when the Window moves. A small Key-keyed cache (a bounded map beside the overrides, cleared on width or wrap change) would match them without breaking "memory proportional to the overrides plus the Window".
- **Anchoring: the Scroll Anchor already does what TanStack had to build.** Because the anchor is an item and an offset, a height change above it moves nothing on screen, which is the case AG Grid calls unavoidable. Worth deciding: what happens when the anchor's own item changes height (keep the offset, clamped, as `clamp_anchor` does now), and whether the "scrolling backward" exception TanStack needed has any analogue (it should not, since binnacle never converts an absolute offset back to an item).
- **Reveal by Key: settle once the Window arrives.** `reveal_key` already waits for `Locate` and then the Window. With content heights, a "start" alignment is exact once the target's own size is known, since the anchor is the target; a "nearest" reveal of a row below the view depends on the heights of rows in between, and needs the AG Grid or TanStack style re-check after the sized Window lands. A bounded retry, as both use, is the precedent.
- **The thumb: accept drift, as everyone does, or improve it with the cache.** No product does better than estimating. A running mean of measured heights in place of the default for unseen rows is the cheapest improvement and stays O(1) memory.
- **What re-measures:** a column width change (every product that wraps), a wrap setting change, an edit to the row, a font or theme change, a terminal resize. AG Grid and MUI X learn of these by observing elements; binnacle would learn of them by Change Notice (content changed), by the Grid's own column resize, and by a host call for theme changes. Only the Window needs re-measuring, so the cost is bounded the way csvlens's and VisiData's per-frame wrap is.
- **Column virtualization must survive.** AG Grid and MUI X give it up because a row's height depends on off-screen cells. binnacle can choose instead: measure only visible columns (MUI X's opt-in, accepting height changes on horizontal scroll), or ask the measurer for all of the row's wrapped columns, which is cheap when only some columns wrap. Worth choosing explicitly.
- **Axis parity.** Columns already take host-measured widths via `AutoSizeRequested`; content widths per Window would mirror content heights. No surveyed product sizes columns to content continuously, only on request, so parity is cheap to keep in the API and need not be used.
- **Rows taller than the body.** csvlens and ratatui cannot show the end of such a row, and VisiData cuts it. binnacle's anchor offset already scrolls within an item; keep that, and a clamp (below) bounds the case.

### For where wrap lives (#276)

- **Per column, not per renderer.** AG Grid's `wrapText`, VisiData's `Column.height` and MUI X's per-row `'auto'` all attach wrap to the data's shape; only csvlens makes it global. Column Presentation in the View Spec matches AG Grid and VisiData and lets a layout save it.
- **Carry a line clamp.** VisiData's `disp_wrap_max_lines` with a placeholder is the only working clamp in the survey, and it keeps tall rows from swallowing the body. On the web, a clamp is also what keeps text measurable on canvas without a DOM.
- **Mark the clamp the way the cut already is.** ratatui's adapter ends a cut value with `…`; VisiData ends a clamped last line with the same `…`. Glide shows nothing, and that is the worse precedent.
- **Wrap at words by default, anywhere as an option.** csvlens offers both (`-W`, `-S`); VisiData has a break-long-words option. Wrap by display width, not characters: csvlens's open PR #211 is the cost of not doing so.
- **Headers by their own setting.** AG Grid keeps `wrapHeaderText` separate from `wrapText`, applies it to groups, and sizes each header row to its tallest cell. In binnacle terms that is per-Tier thickness taking the tallest wrapped label among the Header Spans in view, which the host already sets with `set_tiers`; header wrap then needs the Band's measurement Effect (`BandAutoSizeRequested`) to cover wrapped labels, not a new mechanism. AG Grid has to keep auto-height header columns rendered off-screen to get this right; binnacle would face the same choice.
- **Row-axis parity** (wrapping across columns in a transposed table) has no precedent in the survey.

### For expanding a cut cell (#277)

- **A read-only popover over the cell is the common shape.** Glide's overlay (at least the cell's size, capped width, viewport-limited with its own scroll, read-only preview for read-only cells) and MUI X's recipe are the same idea; AG Grid only has the editing version. Glide's is the one with a keyboard route (Space, Enter).
- **A side pane is the terminal shape.** tabiew's sheet shows the whole row, wraps, scrolls, copies and follows the selection; VisiData's `Enter` pushes a row sheet. For ratatui an overlay over the body or a pane are both precedented; a pane avoids covering neighbouring cells.
- **Keep it apart from the editor's double click and Enter, or merge it deliberately.** Glide merges them: the same overlay is the editor, read-only when the cell is. AG Grid separates them (tooltip versus popup editor). binnacle's double click already begins an edit, so Glide's merge is the closer precedent.
- **It works on any cell in the products that have it,** not only cut ones; MUI X's recipe opens only on overflow, which is why it has no keyboard route (it needs a hover to measure).
- **A Grid Mode with its rect in the Snapshot** matches how the editor already works and gives the C API one place to read it; no surveyed product treats it as an Effect for the host to fill except Glide's custom overlay editors.

### For tooltips (#278)

- **Tooltips show either the full value or host text, and the products that offer both let the host choose per column** (AG Grid `tooltipField`, `tooltipValueGetter`; MUI X header `description`). Two kinds, one surface.
- **"Cut" is known only where text is laid out.** AG Grid and SlickGrid test `scrollWidth > clientWidth` in the DOM; MUI X tests overflow on hover. In binnacle the adapters wrap and clip, so "cut" can stay in the adapter, as the `…` marker already does, unless the core needs it for a keyboard route.
- **Keyboard access is AG Grid's `tooltipTrigger: 'focus'`:** show for the focused cell, immediately. That is the precedent for a keyboard tooltip, and it overlaps with an expand key; treating the expand as the keyboard route and tooltips as the hover route (one feature, two routes) is supported by MUI X, whose hover popover is the expand.
- **Terminals have no tooltips** in the survey; their route is the expand or the pane. ratatui could skip tooltips and rely on #277's answer.
