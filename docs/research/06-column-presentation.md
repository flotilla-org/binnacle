# Hiding and freezing: prior art

How do established grids and table tools hide and freeze items, and what can binnacle borrow? This note answers the research ticket [#132](https://github.com/flotilla-org/binnacle/issues/132) for the map [Column presentation (#131)](https://github.com/flotilla-org/binnacle/issues/131), and feeds the grilling tickets [the hiding model (#134)](https://github.com/flotilla-org/binnacle/issues/134) and [the freezing model (#135)](https://github.com/flotilla-org/binnacle/issues/135). It surveys AG Grid, MUI X, TanStack Table, Glide Data Grid, Handsontable, Perspective with regular-table, Excel, LibreOffice Calc, Google Sheets, WAI-ARIA, and the terminal tools VisiData, csvlens, sc-im, tview, less, lnav, tabiew and ratatui.

The map has settled that hiding and freezing are per axis, with axis parity in every API, and that moves are decided on the same map because freezing raises the same question (can a move cross the frozen edge?). Terms follow [`CONTEXT.md`](https://github.com/flotilla-org/binnacle/blob/main/CONTEXT.md). Two binnacle facts recur below: a Position is gapless by definition, and a `Refiltered` Change Notice already makes focus, picks and the scroll position follow their Keys, with `Locate` able to answer `Gone { suggest }` for a Key that left ([`sort.rs`](https://github.com/flotilla-org/binnacle/blob/ccbad8d/crates/binnacle-core/src/sort.rs#L67-L71), [`refilter.rs`](https://github.com/flotilla-org/binnacle/blob/ccbad8d/crates/binnacle-core/src/refilter.rs)).

Numbering: `docs/research/` on main holds 01 and 02; the research branches add 03 (`research/web-data-grids`), 04 (`research/grid-feature-gaps`) and 05 (`research/filter-models`). 06 is the next free number, as the ticket asked.

## Summary

- **Freezing splits cleanly into two camps.** *Positional* ("the first N"): Excel, LibreOffice, Google Sheets, Glide, Handsontable, csvlens, tview, less. *By identity* ("these columns"): AG Grid, MUI X, TanStack, VisiData, sc-im, and lnav's sticky lines. Every identity-based product either reorders the pinned items to the edge (AG Grid, MUI X, TanStack, VisiData) or freezes them where they stand (sc-im). Handsontable's "Freeze column" bridges the two: it *moves* the column to the freeze line and adds one to the count.
- **Trailing freezing is rarer than leading.** Right-pinned columns exist in AG Grid, MUI X, TanStack and Handsontable develop (`fixedColumnsEnd`, unreleased). Bottom rows exist in AG Grid, MUI X, TanStack, Glide (`freezeTrailingRows`, its only row freeze) and Handsontable (`fixedRowsBottom`). No spreadsheet freezes the bottom or right; no terminal tool does either.
- **A move across the frozen edge does one of three things.** It changes membership by position (Glide, Handsontable develop: the slot is frozen, the count never changes); it pins or unpins the column (AG Grid, unless `lockPinned`); or it is refused (MUI X, Handsontable 18.1.2 once its freeze plugin has been used, VisiData's key columns, Handsontable's trailing edge).
- **Frozen rows and sorting disagree.** Spreadsheets keep a header row out of a sort ("My data has headers"). Handsontable leaves fixed rows out of sorting but in filtering, "on purpose". MUI X's pinned rows ignore sort and filter entirely; AG Grid's static pinned rows likewise; AG Grid's manual pinned rows are *copies* that stay in the body and are filtered with it; TanStack keeps pinned rows on show even when filtered out (`keepPinnedRows`).
- **Hiding a frozen item mostly keeps the frozen set and shrinks the band.** Handsontable keeps `fixedColumnsStart` and draws one column fewer; LibreOffice keeps the split index and draws hidden rows at zero height; Excel counts *visible* rows, so the next row slides in. AG Grid, MUI X and TanStack keep a hidden column's pin, so it comes back pinned.
- **Hiding versus focus is handled badly or not at all.** AG Grid and MUI X leave logical focus on the hidden column (AG Grid's next Right then jumps to column 1, inferred). Handsontable and VisiData move focus to the nearest visible neighbour. On ranges: AG Grid prunes hidden columns out; TanStack v9 keeps a range with a hidden corner in state but ignores it; Handsontable keeps hidden columns inside a wide range so copy includes them, as Excel does by default.
- **Hidden state is a grid concern almost everywhere, frozen state always.** No grid's server protocol carries visibility or pinning (AG Grid SSRM, MUI X data source). The exceptions put hiding in the query: Perspective's view config `columns` list and tabiew's `SELECT`. The spreadsheets split the two: hidden is saved *with the sheet*, freeze *with the window* (Excel `<pane>` under `<sheetView>`, LibreOffice view settings), and Excel's Sheet Views then make hiding per view as well.
- **Scrolling across frozen regions is the same mechanism everywhere:** the frozen part is laid out first at a fixed offset, the scroll offset applies only past it, hit tests check the frozen part first, and a keyboard reveal measures against the viewport less the frozen extent and never scrolls for a frozen target. Page size shrinks by the frozen count (tview).
- **The frozen edge is a line, sometimes a shadow.** AG Grid draws a themable border only; Glide a 1px line plus a shadow that fades in with scroll; MUI X offers `border`, `shadow` or both. In terminals, VisiData and csvlens draw `║` where other separators are `│`; sc-im marks frozen headers with `!`.
- **Controls:** a column-menu "Pin left / Pin right / Unpin" (AG Grid, MUI X); "freeze up to here" at the cursor (Excel, LibreOffice, Google Sheets' "Up to column"); a draggable freeze bar (Google Sheets, Handsontable develop with F6 for keyboard); a searchable checklist chooser (AG Grid, MUI X); Perspective's active and inactive lists; and in terminals VisiData's Columns sheet, `-` hide, `gv` unhide, `!` key, csvlens `f<n>`, sc-im `Zc`, `fc`.

## AG Grid

**Freeze model: by identity, both sides, rows too.** `colDef.pinned` is `'left'`, `'right'` or `true` ([`pinnedColumnService.ts` L258-L263](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/pinnedColumns/pinnedColumnService.ts#L258-L263)); the grid reorders so left-pinned come first and right-pinned last ([column pinning](https://www.ag-grid.com/javascript-data-grid/column-pinning/)). Grid State holds `columnPinning {leftColIds, rightColIds}`, `columnVisibility {hiddenColIds}` and `rowPinning {top, bottom}` as row ids ([`gridState.ts` L158-L165, L237-L242](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/interfaces/gridState.ts#L158-L165)). Rows pin in two modes that cannot be combined ([row pinning](https://www.ag-grid.com/javascript-data-grid/row-pinning/)): manual (`enableRowPinning`, a "Pin Row" context menu), where the pinned row is a *copy* shown at the edge "as well as remaining in the main viewport", linked by `pinnedSibling` ([`manualPinnedRowModel.ts` L481-L512](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/pinnedRowModel/manualPinnedRowModel.ts#L481-L512)); and static `pinnedTopRowData` and `pinnedBottomRowData`, which the user cannot change.

**Moves, sort, filter, hide.** Dropping a column into a pinned area pins it, and holding a drag at the grid edge about a second creates one ([`moveColumnFeature.ts` L112-L114, L620-L675](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/columnMove/columnDrag/moveColumnFeature.ts#L112-L114)). `lockPinned` keeps a column inside its section and drops its pin menu (same file L66-L70; [column pinning docs L40-L51](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/documentation/ag-grid-docs/src/content/docs/column-pinning/index.mdoc#L40-L51)). Dragging a column out of the grid *hides* it unless `suppressDragLeaveHidesColumns` ([column moving](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/documentation/ag-grid-docs/src/content/docs/column-moving/index.mdoc#L46-L105)). `hide` and `pinned` are independent fields of a column's state ([`columnStateUtils.ts` L33-L76](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/columns/columnStateUtils.ts#L33-L76)), so a hidden column keeps its pin (inferred). Manual pinned rows are sorted and filtered with the rest; one filtered out stays pinned in a `hidden` subset and returns when the filter clears ([`manualPinnedRowUtils.ts` L6-L30](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/pinnedRowModel/manualPinnedRowUtils.ts#L6-L30)). Static pinned rows are never sorted, filtered or selected.

**Hiding versus focus, ranges and indexes.** The focus service clears focus only when its column object no longer exists, not when it is hidden ([`focusService.ts` L163-L176](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/focusService.ts#L163-L176)). The DOM cell is destroyed and tries to "recover focus" within 100 ms (same file L92-L110; [`cellCtrl.ts` L1089-L1095](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/rendering/cell/cellCtrl.ts#L1089-L1095)). A hidden column's display index is -1, and `getColAfter` then falls through to the first column ([`visibleColsService.ts` L542-L552](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/columns/visibleColsService.ts#L542-L552)), so Right from a focused hidden column lands on column 1 (inferred). Cell ranges have hidden columns stripped and empty ranges dropped on `columnVisible` ([`rangeService.ts` L324-L348](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-enterprise/src/rangeSelection/rangeService.ts#L324-L348)). `aria-colindex` is assigned over all columns, "hidden cols still take aria slots", and `aria-colcount` counts all columns ([`visibleColsService.ts` L327-L328, L420-L433](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/columns/visibleColsService.ts#L420-L433)).

**Ownership.** Client only. The server-side row model's request carries rows, grouping, pivot, `filterModel` and `sortModel`, but neither visibility nor pinning ([`iServerSideDatasource.ts` L12-L35](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/interfaces/iServerSideDatasource.ts#L12-L35)). Layout is saved with `getColumnState()` and `applyColumnState()` ([column state](https://www.ag-grid.com/javascript-data-grid/column-state/)).

**Scrolling, navigation, edge.** Each row has left and right lanes that are `position: sticky` ([`_general.css` L337-L346](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/theming/core/css/_general.css#L337-L346)), with pinned row sections sticky too. Arrows walk one list (left, centre, right) and the centre scrolls only for an unpinned target ([`navigationService.ts` L917-L932](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/navigation/navigationService.ts#L917-L932)); `ensureColumnVisible` returns early for a pinned column ([`gridBodyScrollFeature.ts` L734-L748](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/gridBodyComp/gridBodyScrollFeature.ts#L734-L748)). The edge is a themable border (`--ag-pinned-column-border`, `pinnedRowBorder`) on the last left-pinned and first right-pinned cells, suppressed where a range edge or focus ring sits ([`pinnedColumnModule.css` L11-L54](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/pinnedColumns/pinnedColumnModule.css#L11-L54)); no shadow. **Too wide:** if pinned widths reach the viewport less 50 px, the grid *unpins* columns, alternating right and left from the outer edge, skipping `lockPinned`; `processUnpinnedColumns` can override, and user resizes are clamped ([`pinnedColumnService.ts` L18-L19, L62-L99, L163-L256](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-community/src/pinnedColumns/pinnedColumnService.ts#L212-L256)).

**Controls.** Column menu "Pin Column" with checked "No Pin", "Pin Left", "Pin Right", plus "Choose Columns" ([`menuItemMapper.ts` L142-L173, L548-L552](https://github.com/ag-grid/ag-grid/blob/1a83d2f62a57646c9327f4b7c3d50c8035eb2b80/packages/ag-grid-enterprise/src/menu/menuItemMapper.ts#L142-L173)). The Columns Tool Panel is a checklist grouped by column group, with search, select all, drag to reorder and optional Apply, Cancel and Reset ([tool panel](https://www.ag-grid.com/javascript-data-grid/tool-panel-columns/)); it has no pin control.

## MUI X Data Grid

**Freeze model: by identity.** `pinnedColumns: {left?: string[], right?: string[]}` by field, ordered `[...left, ...centre, ...right]` ([column pinning](https://mui.com/x/react-data-grid/column-pinning/); [`useGridColumnPinningPreProcessors.ts` L125-L132](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/packages/x-data-grid-pro/src/hooks/features/columnPinning/useGridColumnPinningPreProcessors.ts#L125-L132)). Pinned rows are row *data* given in `pinnedRows: {top, bottom}`, separate from `rows` ([row pinning](https://mui.com/x/react-data-grid/row-pinning/)).

**Moves, sort, hide.** A drag across the edge is refused: "Pinned columns cannot be reordered, except by unpinning and repinning" ([docs L11](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/docs/data/data-grid/column-pinning/column-pinning.md#L11); [`useGridColumnPinning.tsx` L125-L147](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/packages/x-data-grid-pro/src/hooks/features/columnPinning/useGridColumnPinning.tsx#L125-L147)). Unpinning restores the column's position from before it was pinned (`orderedFieldsBeforePinningColumns`, [pre-processors L45-L111](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/packages/x-data-grid-pro/src/hooks/features/columnPinning/useGridColumnPinningPreProcessors.ts#L45-L111)). A hidden pinned column stays in the pinned model. Pinned rows ignore sort, filter and pagination, and cannot be selected or reordered ([row pinning docs L56-L70](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/docs/data/data-grid/row-pinning/row-pinning.md#L56-L70)).

**Hiding versus focus and indexes.** Focus state `{id, field}` is not repaired on hide ([`useGridFocus.ts` L507-L539](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/packages/x-data-grid/src/hooks/features/focus/useGridFocus.ts#L507-L539)); `getColumnIndex` returns -1 for a hidden column. `aria-colindex` is the *visible* index plus one and `aria-colcount` the visible count, so indexes shift on hide ([`GridCell.tsx` L474](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/packages/x-data-grid/src/components/cell/GridCell.tsx#L474); [`useGridAriaAttributes.tsx` L28](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/packages/x-data-grid/src/hooks/utils/useGridAriaAttributes.tsx#L28)), the opposite of AG Grid.

**Ownership.** Client only; the data source's `getRows` gets sort, filter and paging ([`gridDataSource.ts` L9-L37](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/packages/x-data-grid/src/models/gridDataSource.ts#L9-L37)). `columnVisibilityModel` and `pinnedColumns` are controllable and included in `exportState`.

The edge is `pinnedColumnsSectionSeparator: 'border' | 'shadow' | 'border-and-shadow'`, the shadow showing on scroll ([docs L49-L69](https://github.com/mui/mui-x/blob/b6ab5109b9874140088718782c1f36cb7a59a8f7/docs/data/data-grid/column-pinning/column-pinning.md#L49-L69)).

## TanStack Table (headless)

**Freeze model: by identity.** v8 `columnPinning {left, right}`, v9 `{start, end}` (logical, flipping in right-to-left) ([v9 types L17-L20](https://github.com/TanStack/table/blob/95c4768496c07b45b1e65d8e33c3291ac66eae9b/packages/table-core/src/features/column-pinning/columnPinningFeature.types.ts#L17-L20)); `rowPinning {top, bottom}` of row ids. Order is pinning split first, then `columnOrder` within the centre ([`orderByColumnPinning.ts` L23-L60](https://github.com/TanStack/table/blob/95c4768496c07b45b1e65d8e33c3291ac66eae9b/packages/table-core/src/features/column-pinning/orderByColumnPinning.ts#L23-L60)). A hidden pinned column keeps its pin and is filtered after ordering. Pinned rows: `keepPinnedRows` (default true) shows them even when filtered or paged out, in pin order rather than sorted order ([`rowPinningFeature.utils.ts` L108-L198](https://github.com/TanStack/table/blob/95c4768496c07b45b1e65d8e33c3291ac66eae9b/packages/table-core/src/features/row-pinning/rowPinningFeature.utils.ts#L108-L198)).

**Hiding versus selection.** No focus model. v9 cell selection stores ranges by anchor and focus *ids*, resolved against the display order; a range with a hidden corner "contributes nothing while remaining in state" ([types L47-L52](https://github.com/TanStack/table/blob/95c4768496c07b45b1e65d8e33c3291ac66eae9b/packages/table-core/src/features/cell-selection/cellSelectionFeature.types.ts#L47-L52)), so it comes back when the column does.

**Ownership and layout.** All of it is client table state; layout, scrolling, edge and controls are the app's ([v8 pinning guide](https://github.com/TanStack/table/blob/f4dc742b7b8bf01bb7dd10ee7d2f238400befcc0/docs/guide/column-pinning.md#L23)). The useful shape for binnacle is the split accessors: `getLeftVisibleLeafColumns`, `getCenterHeaderGroups`, `row.getRightVisibleCells` and their v9 `start` and `end` renames, one per region, which is what "extra pairs of Strips" amounts to.

## Glide Data Grid (canvas)

**Freeze model: positional.** `freezeColumns: number` freezes the first N columns, the row marker always frozen on top ([API.md L550-L556](https://github.com/glideapps/glide-data-grid/blob/0875d78cc41535a39f8b417ff88ce1ebe129c363/packages/core/API.md#L550-L556)); each column is `sticky: i < freezeColumns` by array index ([`data-grid-lib.ts` L22-L53](https://github.com/glideapps/glide-data-grid/blob/0875d78cc41535a39f8b417ff88ce1ebe129c363/packages/core/src/internal/data-grid/render/data-grid-lib.ts#L22-L53)). `freezeTrailingRows: number` freezes the last N rows ([`data-grid.tsx` L75-L76](https://github.com/glideapps/glide-data-grid/blob/0875d78cc41535a39f8b417ff88ce1ebe129c363/packages/core/src/internal/data-grid/data-grid.tsx#L75-L76)), the totals-row case. There is no leading row freeze and no trailing column freeze; PR [#1059](https://github.com/glideapps/glide-data-grid/pull/1059) proposing `freezeColumns: number | [left, right]` is unmerged.

## WAI-ARIA 1.2 and the APG

`aria-colcount` is the "number of columns in the full table" (-1 if unknown), and `aria-colindex` is needed when "only a portion of the columns is present in the DOM"; it must increase along a row and may have gaps, as the spec's own example (columns 2, 3, 4 and 9 of 16) shows ([aria-colindex](https://www.w3.org/TR/wai-aria-1.2/#aria-colindex)). The APG grade-book example uses indexes 1, 2 and 10 to 13 of 13 because "Columns 3 through 9 are not visible" ([grid and table properties](https://www.w3.org/WAI/ARIA/apg/practices/grid-and-table-properties/)). So both readings of a hidden column are valid ARIA: AG Grid keeps it in the count with a gap, MUI X drops it from both. Neither ARIA nor the APG says what focus does when its column is hidden, or how frozen regions affect reading order; DOM order is row by row regardless of which region a cell is painted in.

**sc-im: per-item frozen flags, rows too, saved in the file.** Any column or row can be frozen; they are drawn in natural order and always shown while mobile ones scroll, so a frozen column on the right acts as a trailing freeze (inferred) ([`tui.c` L759-L770](https://github.com/andmarti1424/sc-im/blob/b5645711b2d2d7d106f93ca5ba2a32b75b49813e/src/tui.c#L759-L770)). Hidden wins over frozen ([`cmds.c` L2590-L2630](https://github.com/andmarti1424/sc-im/blob/b5645711b2d2d7d106f93ca5ba2a32b75b49813e/src/cmds/cmds.c#L2590-L2630)). Both are document state, written as `hidecol A:C` and `freeze A:B` commands and undoable ([`file.c` L436-L490](https://github.com/andmarti1424/sc-im/blob/b5645711b2d2d7d106f93ca5ba2a32b75b49813e/src/file.c#L436-L490)). A frozen header shows `!` after its letter; there is no separator line. Keys `fr`, `fc`, `Zc`, `Zr`, `Sc`, and `:freezecol`, `:hidecol`, `:showcols`.

**tview, less, lnav, tabiew.** tview's `SetFixed(rows, columns)` is positional ("Rows are always the top-most ones"), with page moves of `visibleRows - fixedRows` and no distinct edge glyph ([`table.go` L611-L617, L1605](https://github.com/rivo/tview/blob/c15b79fa47f27032f26647a75cb5a81720255076/table.go#L611-L617)). less `--header=L,C,N` pins L lines and the first C *characters* of each line ([`less.nro.VER` L1881-L1920](https://github.com/gwsw/less/blob/7f46e9ff46216f3e560cd1f41ddf3b36b11eec0e/less.nro.VER#L1881-L1920)), with options to leave headers out of search. lnav's `:hide-fields` hides by field name, and `:toggle-sticky-header` pins specific lines to the top, an identity-based row pin ([`ui.rst` L247-L257](https://github.com/tstack/lnav/blob/753b61bf9c4987342a3f23000ed2a466187d4429/docs/source/ui.rst#L247-L257)). tabiew has neither; choosing columns is a `SELECT` that replaces the frame ([`inline_query_picker.rs` L41](https://github.com/shshemi/tabiew/blob/bd72510f9c33ba20c9b32811d0fe04957a84af80/src/tui/popups/pickers/inline_query_picker.rs#L41)).

## What to borrow

These are options with trade-offs for the grilling tickets, not decisions.

### For #134, the hiding model

**Where hidden state lives.** Three shapes appear in the survey:

1. **The Grid holds a hidden Key set and skips those items itself** (AG Grid, MUI X, Handsontable, VisiData). Positions would no longer be gapless for drawing, so the Grid needs a second index space, which is exactly Handsontable's physical, visual and renderable split and the translation it costs. On a huge axis the Grid cannot skip a long run of hidden items without asking the source, and the Window would fill with keys it does not draw. It also puts per-item state in the Grid, proportional to the number hidden. Not recommended.
2. **The Table Source hides, and the Grid holds the request in the View Spec** (Perspective's `columns` list, tabiew's projection). Hidden items have no Position, so Positions stay gapless, the source answers with a `Refiltered` Change Notice, and focus, picks, Size Overrides and the scroll position already follow their Keys through it, with `Locate` able to answer `Gone { suggest }` for the focused Key. The cost is that every Table Source must support it, including the In-Memory Table Source on the column axis, and a server source sees which items are hidden (flotilla's ADR 0067 would need a way to say so).
3. **Hiding as a Condition in the Filter Spec** (a `not OneOf Keys` on the axis). Cheapest, since the Filter Spec, its declared support and the "items were shown or hidden" path exist, but it muddles two things every spreadsheet keeps apart: Google Sheets has `hiddenByUser` beside `hiddenByFilter`, LibreOffice writes `"collapse"` versus `"filter"`, and Handsontable separates hidden from trimmed. Clearing the filters should not unhide columns, and a chooser should be able to say "hidden by you" versus "filtered out".

**Recommendation:** option 2, as its own part of each axis's View Spec (a list of hidden Keys beside the filter and sort), applied by the source like the rest of the View Spec and answered with `Refiltered`. It keeps Positions gapless, reuses the Refiltered machinery, keeps hiding distinct from filtering in the model while sharing the mechanism, and gives "saving a layout" one place to read: the View Spec. Totals can then read "12 of 30 columns". If the cost to sources is too high, a fallback is an In-Memory default that any source can wrap.

**Focus, selection and picks on hide.** No product handles focus well; Handsontable and VisiData do the sensible thing and move it to the nearest visible neighbour (VisiData: the next to the right, or left at the end). binnacle gets this from `Locate` returning `Gone { suggest }`: recommend the source suggest the next item in the old order, falling back to the previous one, which matches VisiData. For the one contiguous range, the corners carry Keys; hiding an item inside the range shrinks it naturally (Positions are gapless). For a corner that is hidden, choose between AG Grid (prune and drop if empty) and TanStack v9 (keep in state, ignore while hidden). Since binnacle's range is one span, pruning to the remaining Positions is simpler. Picks of hidden rows follow the existing Refiltered rule (dropped), unlike Handsontable, which keeps hidden columns inside a range for copy; Excel copies hidden cells by default too, so whether copy should include hidden items is a question to record for the clipboard work.

**Indexes and ARIA.** With hiding in the source, `aria-colindex` is Position plus one and `aria-colcount` the shown count (MUI X's reading). Keeping hidden items as gaps with a full count (AG Grid's reading, which APG also models) would need the Grid to know the unhidden Position of each item, which it does not have. Recommend the MUI X reading.

**Controls.** Every web grid has "Hide column" in the column menu and a checklist chooser with a search box; Perspective adds drag between shown and hidden lists, and VisiData shows that a chooser can be a table of the columns. For binnacle that suggests the chooser *is* a binnacle Grid over a small Table Source of the column axis's items (name, shown, frozen, width), reusable in ratatui and on the web, with the checklist widget from find and filter as the lighter alternative. ratatui keys: VisiData's `-` and `gv` collide with typing in the default Keymap, so they belong in a modal preset; the column menu covers the default. Mark hidden items where they were: Excel's double line between headers and Handsontable's or Google Sheets' header arrows translate to a thicker gap or a small glyph in the header, with a click to unhide.

### For #135, the freezing model

**Positions or Keys.** This is the central question, and the survey shows why both camps exist.

- **"The first N Positions" per edge (Glide, Handsontable, csvlens, tview, the spreadsheets).** Four numbers per Grid (leading and trailing on each axis), no per-item state, no source involvement, and trivially correct on a huge axis or a virtual source. A move across the edge just changes membership (Glide, Handsontable develop), so it needs no new policy. Its weakness is that the frozen *content* follows the order: sorting the rows changes which rows are frozen, and filtering or hiding a frozen item pulls the next one in. For columns on a host-ordered axis that is usually what people mean ("keep the first two columns"); for rows it is only useful for top-N views.
- **"These Keys" (AG Grid, MUI X, TanStack, VisiData, sc-im).** Matches "pin this column" exactly and survives sort and filter. But every product that does it either reorders the pinned items to the edge or, like sc-im, freezes them in place and lets the rest scroll between them. In binnacle ordering belongs to the Table Source, so a Grid that draws pinned Keys first would draw items out of Position order, breaking a Strip's ordering and the Scroll Anchor's meaning; and a source would have to place them, so pinning becomes a View Spec part and every source must honour it. It also needs a width rule (AG Grid unpins; MUI X only warns).
- **The bridge (Handsontable's ManualColumnFreeze):** keep the model positional, and make "Freeze this column" a *move* of that Key to the frozen edge plus one more frozen item; "Unfreeze" is the reverse move. This gives users Key-shaped controls on a count-shaped model, reuses the movable capability and per-request refusal from [#79](https://github.com/flotilla-org/binnacle/issues/79), and on an axis that cannot move (sorted, or a huge source) the control falls back to "freeze up to here", as Excel and Google Sheets offer.

**Recommendation:** positional counts held by the Grid, leading and trailing on both axes, with "freeze this item" as a move plus a count change where the axis is movable. Defer Key pinning; if it is ever wanted for rows (a "pin this row" the way AG Grid copies a row to the top), model it as AG Grid's manual pinned *copies*: a small Key list the Grid draws in a frozen Strip *in addition to* the body, which never disturbs Positions.

**Grid or source.** Freeze is a Grid concern in every product surveyed, and the spreadsheets go further: it belongs to the *window*, not the document (Excel `<pane>` under `<sheetView>`, LibreOffice view settings), while hidden state belongs to the document. That matches the recommendation above: hidden in the View Spec the source applies, frozen counts in the Grid. "Saving a layout" then reads two places, which is what Excel does too.

**Interactions to settle, with the precedents:**
- *Move across the edge:* membership changes and the count stays (Glide, Handsontable develop) is the natural rule for counts; refusing (MUI X, Handsontable 18.1.2) is the alternative. The drop indicator should show which region the item lands in.
- *Sort on a frozen axis:* with counts, frozen rows are sorted like any other. Handsontable and the spreadsheets keep header rows out of sorting, but binnacle already has Header Bands for headers, so the common need does not arise. Trailing frozen rows for totals are the case that should not sort, and that is a source matter (a totals row is not a data row; Glide's `freezeTrailingRows` and AG Grid's static pinned rows both treat it as separate data).
- *Hide or filter a frozen item:* with hiding in the source and gapless Positions, the next item slides in (csvlens, Excel, Handsontable's trim). The alternative is Handsontable's and LibreOffice's "the count is kept, the band shrinks", which needs the Grid to know which Keys were frozen. A middle path: on `Refiltered`, the Grid already locates the visible Keys, so it could lower the count by the number of frozen Keys that left. Decide which is less surprising.
- *Too wide:* AG Grid unpins (mutates state), Handsontable develop's `limitFixedToViewport` and csvlens clip the drawn band and keep the state, VisiData leaves the cursor unshowable. Recommend clipping: the frozen extent drawn is at most the viewport less a minimum scrolling region, the state is unchanged, and focus in a clipped frozen item still reveals.

**Scrolling, hit-testing and keys.** The pattern is uniform and fits #13's "extra pairs of Strips": a leading frozen Strip, the scrolling Strip and a trailing frozen Strip per axis, crossed to give up to nine regions. The Scroll Anchor applies to the scrolling Strip only, and its Positions start after the leading count and end before the trailing one. Hit testing checks the frozen Strips first at fixed offsets (Glide). A focus move into a frozen item never scrolls, and a reveal measures against the viewport less the frozen extents (Glide, AG Grid, MUI X). Page moves use the scrolling extent (tview). Consider LibreOffice's Ctrl+Home going first to the first unfrozen cell and Handsontable's End stopping before the trailing frozen columns, both of which make edge moves useful with frozen regions. A selection crossing the edge is drawn per region and clipped (Handsontable's overlays), which the Snapshot's selection rects can carry per region.

**Drawing the edge.** Web: a line in the Theme's border colour at the frozen extent (Glide, AG Grid), with an optional shadow that appears only once the scrolling region has moved (Glide, MUI X), so an unscrolled grid looks unfrozen. ratatui: VisiData's and csvlens's `║` in place of `│`, with csvlens's `╥` and `╨` caps where the header rule meets it, is the established terminal idiom and maps onto Border Styles. A Border Style without vertical rules needs another mark, such as sc-im's `!` or VisiData's key colour.

**Controls.** Column menu items "Freeze up to here" and "Unfreeze" (Excel's cursor-based freeze, Google Sheets' "Up to column"), plus "Freeze this column" where the axis is movable; trailing equivalents for the last items. A draggable freeze bar is the most direct control and Handsontable's F6-then-arrows gives it a keyboard path; in ratatui, csvlens's `f<n>` (a count prompt) is the precedent, again for a modal preset.

**Accessibility.** DOM reading order stays row by row whatever region a cell is painted in, so the hidden ARIA table should list each row's cells in Position order across frozen and scrolling regions, with `aria-colindex` from Positions as above. Nothing in ARIA marks an item as frozen.
