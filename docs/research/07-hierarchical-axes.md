# Grouping, subtotals and pivots: prior art

How do established grids and pivot tools group, subtotal and pivot, and what can binnacle borrow? This note answers the research ticket [#178](https://github.com/flotilla-org/binnacle/issues/178) for the map [Hierarchical axes (#177)](https://github.com/flotilla-org/binnacle/issues/177). It surveys Perspective with regular-table, AG Grid (row grouping, tree data, pivot mode, the server-side row model), TanStack Table, Excel, Google Sheets, VisiData, Tad and quantrish.

Terms follow [`CONTEXT.md`](https://github.com/flotilla-org/binnacle/blob/main/CONTEXT.md). One clash to keep in mind: binnacle's **Totals** is an axis's count before any filter. This note says *grand total* and *subtotal* for aggregate items, never "Totals", and the map should pick a term for them that does not collide. Binnacle facts that recur below: a Position is gapless by definition; a Key is an opaque 64-bit identity the Table Source assigns, with a Key Interner to map composite identities to Keys; Size Overrides follow their Keys; and a `Refiltered` Change Notice makes focus, picks and the scroll position follow their Keys, while `Inserted` and `Removed` move them by Position ([`notice.rs`](https://github.com/flotilla-org/binnacle/blob/7f4a29f/crates/binnacle-core/src/notice.rs#L19-L60)).

Numbering: `docs/research/` on main holds 01 and 02; the research branches add 03 to 06. 07 is the next free number, as the ticket asked.

## Summary

- **Subtotals are computed by whatever owns the data, never by a drawing layer.** Perspective's engine, Tad's SQL, AG Grid's row model stages (client side) or the server (SSRM), Excel's pivot engine and quantrish's engine all compute them. No product asks the grid to aggregate values it has been handed. For binnacle that means the Table Source, which already owns roll-up in `CONTEXT.md`.
- **A subtotal reaches the grid as an ordinary row with a kind flag, at a place the view config chooses.** Perspective makes the group row *be* the subtotal and puts it before its children, with a grand total row first (`group_rollup_mode: "rollup"`). AG Grid has a group row plus an optional separate total row, `groupTotalRow: 'top' | 'bottom'`, and a grand total row top or bottom or pinned. Excel offers subtotals at top or bottom per field (`subtotalTop`), and quantrish offers `Off | After | Before | Both` per band. Tad always puts the parent before its children and has an optional grand total "top row".
- **Group identity is a path of values in every product.** AG Grid uses `row-group-<col>-<key>-<col>-<key>`, with total rows as `rowGroupFooter_<group id>`. TanStack uses `col:value>col:value`. Perspective uses `__ROW_PATH__` (the value array), Tad an encoded path, Excel field item indexes, Google Sheets the group's value, and quantrish an `AxisPath` of `Item { category, item }` or `Subtotal { category }` selectors. A subtotal or total item is identified by its group's path plus a kind.
- **Expand and collapse state lives in one of three places.** (1) In the engine, keyed by tree node and addressed by row Position: Perspective's traversal, where new groups arrive collapsed. (2) In saved view state, keyed by path: Tad's `openPaths` trie, AG Grid's `expandedRowGroupIds`, Excel's per-item `sd` flag and Google Sheets' `collapsed` per value. (3) Thrown away on data change: TanStack's default `autoResetExpanded`. Path-keyed state survives sort, filter and data changes; Tad trims it to the unchanged prefix when the grouping columns change.
- **Collapsed children have no row index anywhere.** Tad's tree query unions only the open paths and counts the result in SQL; AG Grid SSRM clears a collapsed child store's display indexes; Perspective's traversal holds only visible nodes. Counts and scroll extents are therefore those of the visible tree, which matches binnacle's gapless Positions. Expanding a group is an insertion after the group row.
- **Spanning headers come in two models.** AG Grid has an explicit column group tree, with padding groups for uneven depth. A group split by a move or pin becomes several drawn instances, and `marryChildren` refuses moves that would split it. Perspective with regular-table and quantrish instead *derive* spans by merging adjacent header cells with equal values at each level. The derivation compares labels, not paths, so two adjacent groups with the same label under different parents would merge (inferred for both).
- **Pivot columns are named by their path plus the value column.** AG Grid uses `pivot_<pivot cols>_<keys>_<value col>`, Perspective `"CA|First Class|Sales"`, VisiData the value itself (`count_CA` when several aggregators), and quantrish an `AxisPath`. What survives a change of values differs. AG Grid keeps column state and user order by that id across regenerations. Perspective's datagrid keeps widths by path, but *not* when `split_by` is set, where they stay positional. Excel autofits on update by default and does not keep a custom item order across a refresh.
- **Filters apply before aggregation by default** (Perspective's `filter` is SQL `WHERE`; Tad filters the base query; Google Sheets `filterSpecs` apply "before aggregating"; AG Grid's filter stage runs before its aggregate stage). Filtering on aggregates is an extra: AG Grid's `groupAggFiltering`, and Excel's value filters. Whether subtotals include filtered-out items is a switch in Excel ("Include Filtered Items in Totals") and in AG Grid (`suppressAggFilteredOnly`); quantrish's subtotals currently include items a slicer hides (inferred, below).
- **Sorting is within each parent, by the sort column's aggregate**, with parents kept before their children (Perspective's traversal `sort_by`, Tad's `_sortVal_<i>` columns, AG Grid's group sort). Total rows are placed after sorting, not sorted.
- **Controls:** drop zones for Row Groups, Values and Column Labels (AG Grid), the four-area field list (Excel, Google Sheets), Group By and Split By lists with a rollup mode selector (Perspective), a Pivot tab with "Show Global Aggregations as Top Row" (Tad), dragging categories onto the side or top strip with an Off/After/Before/Both popover (quantrish). Expansion uses chevrons, with Shift-click to expand or collapse a whole level (Perspective), or Excel's `+`/`-` buttons and level buttons. In the terminal, VisiData has no in-place grouping: `F` opens a frequency table, `W` a pivot, and Enter dives into a group's source rows.

## Perspective and regular-table

**Where totals are computed and placed.** The engine computes every aggregate. `group_rollup_mode` decides which rows exist: `"rollup"` gives "the full hierarchy, with a subtotal row for every group at every level and a grand total row, each addressable by its `__ROW_PATH__`"; `"flat"` gives leaf groups only, "useful for chart plugins and exports where subtotal rows would double-count"; `"total"` gives the grand total row alone ([`grouping_and_pivots.md` L41-L54](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/docs/md/explanation/view/config/grouping_and_pivots.md#L41-L54); [`view_config.rs` L27-L38](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-client/src/rust/config/view_config.rs#L27-L38)). There is no "subtotal after": a group row is its own subtotal and sits before its children. Columns have the counterpart `split_rollup_mode`: `"flat"` (the default) emits only full-depth split combinations, `"rollup"` adds a grand total column per aggregate and subtotal columns that "precede their groups, in pre-order" (same doc, L120-L133; [`view_config.rs` L70-L84](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-client/src/rust/config/view_config.rs#L70-L84)). `num_view_rows` "will also include aggregated rows" ([`view.rs` L373-L380](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-client/src/rust/view.rs#L373-L380)).

**Identity.** Group rows carry `__ROW_PATH__`, the array of group values. The datagrid keys rows by `__ID__` joined with `|` and columns by their path string ([`data_listener/index.ts` L186-L201](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/packages/viewer-datagrid/src/ts/data_listener/index.ts#L186-L201)). A split column is named by its split values and the column name joined with `|`, for example `"CA|Sales"`. `column_paths` returns the header area as `area[level][column]`, one level per `split_by` plus one, with subtotal and grand total columns reading null at the levels they do not split on ([`view.rs` L327-L341](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-client/src/rust/view.rs#L327-L341)).

**Expand and collapse: in the engine, addressed by Position.** The API is `expand(row_index)`, `collapse(row_index)` and `set_depth(depth)` ([`view.rs` L731-L757](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-client/src/rust/view.rs#L731-L757)), and `group_by_depth` in the view config ([`view_config.rs` L115-L155](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-client/src/rust/config/view_config.rs#L115-L155)). The state is an `m_expanded` flag on each node of the traversal, a pre-order vector of the *visible* tree nodes, each pointing at its tree node by `m_tnid` ([`traversal_nodes.h` L20-L27](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-server/cpp/perspective/src/include/perspective/traversal_nodes.h#L20-L27)). A manual open or close turns off automatic depth ([`context_one.cpp` L88-L121](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-server/cpp/perspective/src/cpp/context_one.cpp#L88-L121)). Otherwise each update re-applies the depth after sorting (same file, L340-L354). On an update, groups that vanished are dropped from the traversal, and a new group is inserted *collapsed* among its siblings ([`tree_context_common.cpp` L73-L84](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-server/cpp/perspective/src/cpp/tree_context_common.cpp#L73-L84); [`traversal.cpp` L242-L272](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-server/cpp/perspective/src/cpp/traversal.cpp#L242-L272)). Because the state is on the view's traversal, a new view (any config change) starts again from the depth (inferred). The datagrid's click handler sends `collapse(meta.y)` or `expand(meta.y)` with the clicked row's Position, Shift-click sets the depth to the clicked level, and then it re-reads `num_rows` and redraws ([`expand_collapse.ts` L15-L48](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/packages/viewer-datagrid/src/ts/event_handlers/expand_collapse.ts#L15-L48)).

**Sort and filter.** Sorting reorders the children of each expanded parent by their aggregates, and parents keep their place before their children ([`traversal.h` L170-L283](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-server/cpp/perspective/src/include/perspective/traversal.h#L170-L283)). `"col asc"` and `"col desc"` sort the split column groups ([`selection_and_ordering.md` L37-L46](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/docs/md/explanation/view/config/selection_and_ordering.md#L37-L46)). `filter` is "analogous to the `WHERE` clause in SQL", so it applies to source rows before aggregation (same doc, L87-L94); there is no filter on aggregates.

**Headers and spans.** Group values are drawn as row headers, `group_by.length + 1` levels deep in `"rollup"` mode ([`data_listener/index.ts` L388-L398](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/packages/viewer-datagrid/src/ts/data_listener/index.ts#L388-L398)), and the column header has one level per split plus one, with `column_header_merge_depth` set to the split count (same file, L344-L357). regular-table merges column header cells at each level above the merge depth when the cell's value equals the previous cell's at that level, growing a `colspan` ([`thead.ts` L172-L196](https://github.com/finos/regular-table/blob/52e86bf8b74fc5948bb0047afbc8bb9207dd933c/src/ts/thead.ts#L172-L196)); row headers merge the same way into `rowspan` or `colspan` ([`tbody.ts` L136-L155](https://github.com/finos/regular-table/blob/52e86bf8b74fc5948bb0047afbc8bb9207dd933c/src/ts/tbody.ts#L136-L155)). The test is the value at that level alone, so adjacent groups with equal labels under different parents would merge (inferred), and a span is only as wide as the rendered window.

**Pivot column identity and widths.** Widths are reconciled against "the path-keyed truth", except that with `split_by` set the function returns regular-table's live overrides, which are keyed by column index ([`column_overrides.ts` L22-L35](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/packages/viewer-datagrid/src/ts/model/column_overrides.ts#L22-L35)). So on a pivot a resized width stays with the slot when the split values change (inferred).

**Controls.** The settings panel has Group By, Split By, Order By and Where lists that columns are dragged into, with a group rollup selector and a split rollup selector beside them and a "Transpose Pivots" button ([`config_selector.rs` L611-L730](https://github.com/perspective-dev/perspective/blob/0857a7d9c1e34f9d82496b8a81f6778944178b85/rust/perspective-viewer/src/rust/components/column_selector/config_selector.rs#L611-L730)).

## AG Grid

**Where totals are computed and placed.** The client-side row model is a pipeline: group, filter, pivot, aggregate, filter aggregates, sort, map ([`clientSideRowModel.ts` L766-L786](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/clientSideRowModel/clientSideRowModel.ts#L766-L786)). The aggregate stage aggregates `childrenAfterFilter` unless `suppressAggFilteredOnly` (or `groupAggFiltering`) asks for all children, and aggregates the root when a grand total or pivot mode needs it ([`aggregationStage.ts` L156-L159, L267](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/aggregation/aggregationStage.ts#L156-L159)). Placement happens when the tree is flattened into displayed rows. A group total row exists only while its group is expanded, `'top'` before the children and `'bottom'` after. A grand total row needs at least one row and can be put first, put last or pinned (handed to the pinned row model instead) ([`flattenStage.ts` L54-L71, L117-L153](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/rowHierarchy/flattenStage.ts#L54-L71)). With the server-side row model the server supplies aggregates in the group rows' data and the grand total through `success({ grandTotalData })` ([`iServerSideDatasource.ts` L49-L58](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/interfaces/iServerSideDatasource.ts#L49-L58)); the grid still decides where total rows go ([`lazyStore.ts` L313-L340](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/serverSideRowModel/stores/lazy/lazyStore.ts#L313-L340)).

**Identity.** A group's id is `'row-group-' + colId + '-' + key`, with `'-' + colId + '-' + key` appended per level. The node carries `group`, `key`, `level`, `field`, `rowGroupColumn` and `leafGroup`, and group nodes are cached and reused by id ([`groupStrategy.ts` L514-L570](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/rowGrouping/groupStrategy/groupStrategy.ts#L514-L570)). A total row is a sibling clone of its group with `footer = true` and id `'rowGroupFooter_' + group.id`, created once and reused; the grand total is `rowGroupFooter_ROOT_NODE_ID` ([`footerUtils.ts` L4-L30](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/aggregation/footerUtils.ts#L4-L30); [`iRowNode.ts` L240-L259](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/interfaces/iRowNode.ts#L240-L259)). `getRowId` receives `parentKeys` and `level`, and an id starting `row-group-` is an error ([`rowNode.ts` L481-L496](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/entities/rowNode.ts#L481-L496)). Tree data takes a path per row (`getDataPath`) and makes "filler" groups for missing levels ([`treeGroupStrategy.ts` L512-L545](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/treeData/treeGroupStrategy.ts#L512-L545)).

**Expand and collapse.** The flag is `rowNode._expanded`; `null` means "not decided", resolved from `groupDefaultExpanded` (a depth, or -1 for all) or `isGroupOpenByDefault` and then cached ([`csrmExpansionService.ts` L66-L82](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/rowHierarchy/csrmExpansionService.ts#L66-L82); [`baseExpansionService.ts` L56-L81](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/rowHierarchy/baseExpansionService.ts#L56-L81)). Saved grid state keys it by row id: `expandedRowGroupIds`; on the server-side model also `collapsedRowGroupIds`, or `{ expandAll, invertedRowGroupIds }` under `ssrmExpandAllAffectsAllRows` ([`iExpansionService.ts` L5-L26](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/interfaces/iExpansionService.ts#L5-L26)). Since the id is the value path, expansion survives sort and filter (which never rebuild nodes) and a regroup ("preserve selection and expansion state", [`groupStrategy.ts` L533-L540](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/rowGrouping/groupStrategy/groupStrategy.ts#L533-L540)). New row data without `getRowId` destroys every group node, so expansion is lost ([`clientSideNodeManager.ts` L62-L72](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/clientSideRowModel/clientSideNodeManager.ts#L62-L72)). On the server-side model a child store is created on expand. A collapsed group's store gets `clearDisplayIndexes`, so it adds no rows and no height, and it is destroyed only under `purgeClosedRowNodes` ([`serverSideExpansionService.ts` L209-L221](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/serverSideRowModel/services/serverSideExpansionService.ts#L209-L221)); `getChildCount` only feeds the count shown in the group cell.

**Display.** `groupDisplayType` puts group labels in a single auto column, one auto column per level, or full-width group rows. `groupHideOpenParents` hides an expanded parent and lets its children carry its label ([`flattenUtils.ts` L18-L86](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/rowHierarchy/flattenUtils.ts#L18-L86)). The group cell shows `allChildrenCount` unless `suppressCount` ([`groupCellRendererCtrl.ts` L369-L392](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/rowHierarchy/rendering/groupCellRendererCtrl.ts#L369-L392)).

**Spanning headers: an explicit tree, split into instances.** Column groups are declared as a tree; a column shallower than the tree gets padding groups down to its depth ([`buildColumnTree.ts` L310-L330](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/columns/buildColumnTree.ts#L310-L330)). For each pinned section, every adjacent run of displayed columns with the same declared parent becomes one drawn group. A group split by a move or a pin is therefore drawn as several instances, numbered per group id across the sections ([`columnGroupService.ts` L60-L125](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/columns/columnGroups/columnGroupService.ts#L60-L125)). Each instance's width is the sum of its displayed children ([`agColumnGroup.ts` L91-L110](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/entities/agColumnGroup.ts#L91-L110)). `marryChildren` refuses a move that would split a group ([`columnMoveUtils.ts` L72-L123](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/columnMove/columnMoveUtils.ts#L72-L123)). A column group also expands and collapses: `columnGroupShow: 'open' | 'closed'` picks which children show in each state, and a group is expandable only if both states show something ([`agProvidedColumnGroup.ts` L229-L260](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-community/src/entities/agProvidedColumnGroup.ts#L229-L260)).

**Pivot.** Result column ids are `pivot_<pivot col ids>_<pivot keys>_<value col id>`, and group ids `pivotGroup_<pivot col ids>_<keys>` ([`pivotColDefService.ts` L580-L588](https://github.com/ag-grid/ag-grid/blob/71ac92a58d987b86cb9a30a955611eb75ed200ce/packages/ag-grid-enterprise/src/pivot/pivotColDefService.ts#L580-L588)). Row totals (`pivotRowTotals`) and column group totals (`pivotColumnGroupTotals`) go `'before'` or `'after'` (same file, L358-L466). `pivotDefaultExpanded` opens pivot column groups to a depth, with the leaf columns shown only when open (L240-L268). ## Excel

**Where totals are computed and placed.** The pivot table definition stores layout but no subtotal values, so the engine computes them from the pivot cache on refresh (inferred; `refreshOnLoad` "will refresh the cache when the workbook has been opened", [`PivotCacheDefinition`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.pivotcachedefinition)). Placement is per field: `subtotalTop` says "whether to display subtotals at the top of the group. Applies only when *Outline* is *true*" ([`PivotField`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.pivotfield)). The UI offers "Do Not Show Subtotals", "Show all Subtotals at Bottom of Group" and "Show all Subtotals at Top of Group", and grand totals for rows and for columns separately ([show or hide subtotals](https://support.microsoft.com/en-us/office/show-or-hide-subtotals-and-totals-in-a-pivottable-fc4d8406-f230-4762-aa2f-310826f3e5e2)). Office.js has `subtotalLocation: "AtTop" | "AtBottom" | "Off"`, `layoutType: "Compact" | "Tabular" | "Outline"`, and `showRowGrandTotals` and `showColumnGrandTotals` ([`PivotLayout`](https://learn.microsoft.com/en-us/javascript/api/excel/excel.pivotlayout)). Compact form "displays items from different row area fields in one column"; tabular form "displays one column per field" ([layout and format](https://support.microsoft.com/en-us/office/design-the-layout-and-format-of-a-pivottable-a9600265-95bf-4900-868e-641133c05a80)). That is the same choice as AG Grid's single versus multiple group columns. Separately, Data > Subtotal writes `SUBTOTAL` formulas into ordinary cells and "outlines the list so that you can display and hide the detail rows", with "Summary below data" choosing the side ([insert subtotals](https://support.microsoft.com/en-us/excel/insert-subtotals-in-a-list-of-data-in-a-worksheet); `summaryBelow` in [`OutlineProperties`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.outlineproperties)).

**Identity.** Each laid-out row or column is an `<i>` item. Its `t` is the item type (`data`, `default`, `sum`, `countA`, `avg`, ..., `grand`, `blank`), its `<x v>` children index into each field's items, and `r` counts how many leading entries repeat the previous item ([`RowItem`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.rowitem); [`ItemValues`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.itemvalues)). The `r` count is a path with a shared-prefix length, which is exactly what a spanning header needs (inferred). So a subtotal row is a path plus a kind.

**Expand and collapse.** The `sd` ("show details") attribute sits on a field's `<item>`, so the state is keyed by field and item, not by worksheet row ([`Item`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.item)). Office.js exposes it as `PivotItem.isExpanded` ([`PivotItem`](https://learn.microsoft.com/en-us/javascript/api/excel/excel.pivotitem)). The UI has "Expand Entire Field", "Collapse Entire Field" and "Expand To <field>" ([expand or collapse](https://support.microsoft.com/en-us/excel/expand-collapse-or-show-details-in-a-pivottable-or-pivotchart)). Keying by item (inferred) means collapsing "East" collapses it under every parent, unlike AG Grid and Tad, which key by full path.

**Pivot identity on refresh.** "Autofit column widths on update" is on by default, and "Preserve cell formatting on update" keeps formats ([PivotTable options](https://support.microsoft.com/en-us/office/pivottable-options-27c02eb7-27de-4b3f-9677-c48e3fe7637b)). `hideNewItems` hides items that appear after a refresh ([`PivotField`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.pivotfield)). Items can be dragged into a manual order, but "A custom list sort order is not retained when you update (refresh) data" ([sort a PivotTable](https://support.microsoft.com/en-us/excel/sort-data-in-a-pivottable-or-pivotchart)).

**Sort and filter.** Items can be sorted by a value field's totals (`autoSortScope`, or `sortByValues` with a `pivotItemScope` naming the row or column to sort on, [`PivotField` (Office.js)](https://learn.microsoft.com/en-us/javascript/api/excel/excel.pivotfield)). Report filters, slicers, label filters and value filters (Top 10) all exist ([filter data in a PivotTable](https://support.microsoft.com/en-us/excel/get-started/filter-data-in-a-pivottable)). "Include Filtered Items in Totals" and "Subtotal filtered page items" decide whether filtered-out items count in totals. What focus, selection and copy do on subtotal rows is not documented.

**Controls.** The PivotTable Fields pane with Filters, Columns, Rows and Values areas ([field list](https://support.microsoft.com/en-gb/office/use-the-field-list-to-arrange-fields-in-a-pivottable-43980e05-a585-4fcd-bd91-80160adfebec)); `+`/`-` buttons on items; for outlines, level buttons 1, 2, 3 to show only the subtotals.

quantrish is a pivot-first cube viewer whose spec rejects flat-grid libraries because "hierarchical stacked headers, subtotal rows ... axis-symmetric addressing" are out of their scope ([spec L127](https://github.com/rjwittams/quantrish/blob/ae5ed793b96c45c014102eb18ea512e673ca3bfa/docs/superpowers/specs/2026-04-15-quantrish-design.md#L127)). **Identity and placement.** Every position on an axis is an `AxisPath`, one `ItemSelector` per band, either `Item { category, item }` or `Subtotal { category }`, and a cell is the pair of side and top paths ([`path.rs` L7-L42](https://github.com/rjwittams/quantrish/blob/ae5ed793b96c45c014102eb18ea512e673ca3bfa/engine/src/viewport/path.rs#L7-L42)). Subtotal cells are read-only and never show an adjustment ([spec L304](https://github.com/rjwittams/quantrish/blob/ae5ed793b96c45c014102eb18ea512e673ca3bfa/docs/superpowers/specs/2026-04-15-quantrish-design.md#L304); `compute_cell_base`, render.rs L198-L215).

## What to borrow

These are options with trade-offs for the map's decisions, not decisions.

**Where subtotals are computed: the Table Source.** Every product computes them where the data lives, and `CONTEXT.md` already gives roll-up and pivot to the Table Source. The Grid never sees values, so it cannot aggregate, and it should not need to.

**How they are placed: as items on the axis, chosen by the View Spec.** Every product with subtotals draws them as ordinary rows (or columns) in the flattened order, with a kind flag. In binnacle that means a subtotal or grand total is an item with a Position and a Key like any other, so Positions stay gapless, and Strips, hit testing, focus and scrolling need nothing new. The placement choice belongs in the View Spec per grouping level. quantrish's `Off | After | Before | Both` covers Excel's top or bottom, AG Grid's `groupTotalRow` and Perspective's before-only shape. A grand total is the outermost level's subtotal, and AG Grid's pinned grand total maps onto doc 06's trailing frozen rows, which already flagged a totals row as the case that should not sort. Two rules from the survey to adopt: total rows are placed after sorting and are not sorted themselves, and parents stay before (or after) their children whatever the sort (Tad's `_sortVal`, Perspective's per-parent sort). The same View Spec part on the column axis gives totals on pivot columns for free, as quantrish shows.

**How group items are identified: a path plus a kind, interned to a Key.** All products name a group by its path of values, and a total row by its group's path plus a marker (AG Grid's `rowGroupFooter_` prefix, quantrish's `Subtotal` selector, Excel's `t`). For binnacle the Table Source interns `(path, kind)` through the Key Interner. Because the path is stable, the Key survives sorting, filtering and data changes, exactly what AG Grid relies on when it reuses group nodes by id. The Grid then needs, per item in the Window, a few flags beside the Key: kind (leaf, group, subtotal, grand total), depth, and for a group whether it is expandable and expanded. Those are drawing hints like find marks or Unmatched Rows, not state the Grid owns. Avoid AG Grid's string ids built by concatenation: its own `getRowId` has to forbid the `row-group-` prefix to avoid collisions, which the Key Interner exists to prevent.

**Where expand and collapse state lives: in the View Spec, keyed by group Key.** Three homes were found:

1. *In the source's engine, addressed by Position* (Perspective). Simple for the source, but the state dies with the view, arrives collapsed for new groups, and Position-addressed expand races with updates.
2. *In declared view state, keyed by path* (Tad's `openPaths`, AG Grid's `expandedRowGroupIds`, saved state in Excel and Sheets). It survives sort, filter and data changes, saves with the layout, and Tad's trim-on-regroup shows what to do when the grouping changes.
3. *Thrown away on data change* (TanStack's default). Not suitable for live data.

Recommend option 2: each axis's View Spec gains its grouping plus an expansion part. Following AG Grid's server-side shape, the expansion part is a default depth plus a set of group Keys inverted from that default (`{ expandAll, invertedRowGroupIds }`), so "expand all" on a huge axis is one flag, not a set proportional to the groups. That is the one per-item set the Grid would hold, and it is proportional to what the user toggled, not to the axis. Since the Keys are interned from paths, the source can match them across data changes and drop the ones whose groups vanished. The toggle is a View Edit (expand or collapse this Key, or set the depth) on the latest requested spec, which the source applies and answers with a Change Notice. Expanding one group is an `Inserted` of its children after it, and collapsing is a `Removed`, so focus, the range and the Scroll Anchor follow by Position as they already do. A source that cannot say what changed answers `Reset`, and Keys still carry focus through it. Excel and Google Sheets key collapse by *value* (collapse "East" everywhere); that is a different and coarser control, best offered as "collapse this level" (Perspective's Shift-click `set_depth`).

**What a collapsed group does to counts and scrolling.** In every product collapsed children have no index, and counts are of the visible tree (Tad counts in SQL; AG Grid SSRM gives a collapsed store no display indexes). That is binnacle's gapless Position already: the axis count the source reports is the visible count, and Totals (the unfiltered count) stays the leaf count before filtering, or unknown. For a huge server-side axis the source must be able to answer the count and a Window from the expansion state alone, which Tad's open-paths query and AG Grid's per-group stores both show is practical.

**Focus, selection and copy on group items.** No surveyed grid has special focus rules for group rows, so binnacle needs none. Group items are focusable items. Two behaviours to adopt from AG Grid and VisiData: selecting a group item can stand for its descendants (`groupSelects`, VisiData's bin selection), which is a source question when picks are exported; and copy includes group and total rows by default with a way to skip them. Subtotal cells are not editable (quantrish), which the source can declare through the existing per-request edit refusal.

**Filtering before or after aggregation.** Before is the default everywhere and is what the existing Filter Spec means. Filtering on aggregates is an extra (AG Grid, Excel value filters). If wanted later it is a Condition that names an aggregate, not a change to the model. The map should say whether subtotals count filtered-out leaves (Excel and AG Grid make it a switch), since quantrish currently counts them by accident.

**Spanning headers: derive spans from group Keys, not labels.** The derived model (regular-table, quantrish) fits binnacle best, because the Grid draws what the Window gives it and has no column tree to declare. But it must compare the group identity at each level, not the label, or adjacent groups with equal names under different parents merge. Concretely, each item of the column axis would carry, per header level, the Key of its group at that level (and Excel's `r`, a shared-prefix length, is a compact equivalent). The Grid merges adjacent items in a Strip whose group Keys at a level are equal, and the Header Band's thickness becomes the number of levels times the level height. Two edge cases from the survey: a span that starts before the Window is clipped, so its label should stick to the visible start (inferred from regular-table drawing only the rendered window); and a move that splits a group draws it as two spans (AG Grid's instances), which falls out of adjacency for free. AG Grid's `marryChildren`, refusing such moves, maps onto the per-request move refusal from #79. The row axis is symmetric: group labels can be drawn as a multi-level row Header Band (Perspective's row headers, quantrish's side bands) or as a column in the body (AG Grid's auto group column, Excel's compact form). The first keeps axis parity and matches "headers live in Header Bands".

**Pivot column identity.** Every product names pivot columns by `(pivot path, value column)`. Interned to Keys, binnacle's Size Overrides then follow pivot columns across value changes with no new mechanism, which is AG Grid's behaviour and better than Perspective's positional fallback under `split_by` or Excel's autofit-on-refresh. A user's column order on a pivot should be kept as AG Grid does (restore by id, new columns placed by the source's order), which is a source concern since moves belong to the source. When new pivot values appear, the source answers `Inserted`; when values vanish, `Removed` or `Refiltered`, so nothing is reset. Pins (doc 06 recommended positional frozen counts) need no change, but freezing "the first N" on a pivot axis freezes whichever columns land there; the row Header Band, not a frozen count, should hold group labels.

**Controls.** Web: a grouping panel above the header with drop zones (AG Grid), or "Group by" and "Pivot by" in the column menu, with a rollup selector for subtotal placement (Perspective, quantrish's popover). Chevrons on group items toggle one group, a modifier toggles the whole level (Perspective), and level buttons set the depth (Excel). ratatui: no terminal tool groups in place, so there is no established keymap. VisiData's `F` and `W` open new sheets instead. Reasonable defaults that do not clash with existing bindings would be `Enter` or Space on a group item to toggle, Left and Right on a group item to collapse and expand (as tree widgets do), and a modal prompt for depth, but these are binnacle's to choose.
