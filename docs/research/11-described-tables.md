# Described tables: how generic table viewers type, format and act on data

Research ticket [#283](https://github.com/flotilla-org/binnacle/issues/283), under the map [#281](https://github.com/flotilla-org/binnacle/issues/281). The question: how do viewers that never had per-table code written for them format values by type, order them, decide what to show, offer row actions and follow references? The viewers are `kubectl get` and k9s, Datasette, Grafana's data frames and Table panel, Perspective and VisiData. The answers feed the described-table source (#284), its ordering and default display (#285), its CLI host (#288) and host-defined row actions (#289).

## kubectl

**Types and formatting.** A server `Table` is column definitions plus rows of cells, one per column ([types.go L1465-L1502](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/apimachinery/pkg/apis/meta/v1/types.go#L1465-L1502)). Each column has an OpenAPI `type`, a `format` (`name` marks the primary identifier) and an int `priority`. A CRD's `additionalPrinterColumns` add `jsonPath` ([apiextensions types.go L227-L249](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/apiextensions-apiserver/pkg/apis/apiextensions/v1/types.go#L227-L249)), with `type` limited to `integer|number|string|boolean|date` ([validation.go L831-L838](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/apiextensions-apiserver/pkg/apis/apiextensions/validation/validation.go#L831-L838)).

The CRD table convertor coerces each value to the declared type and gives up to `nil` otherwise: a numeric string in an `integer` column, a nested object in a non-string column, a missing path ([tableconvertor.go L141-L189](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/apiextensions-apiserver/pkg/registry/customresource/tableconvertor/tableconvertor.go#L141-L189)). A `date` becomes a relative age string *on the server*, at request time, or the literal `<invalid>` when it does not parse. The age uses two or three significant figures (`45s`, `3m12s`, `5h20m`, `12d`; [duration.go L48-L93](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/apimachinery/pkg/util/duration/duration.go#L48-L93)). The client prints `nil` as an empty cell and everything else with `fmt.Sprint` ([tableprinter.go L300-L311](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/cli-runtime/pkg/printers/tableprinter.go#L300-L311)). The docs say `format` "controls the style used when kubectl prints the value" ([CRD docs](https://kubernetes.io/docs/tasks/extend-kubernetes/custom-resources/custom-resource-definitions/#additional-printer-columns)), but the printer reads `format` only for `name`, to add a `kind/` prefix ([tableprinter.go L433-L522](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/cli-runtime/pkg/printers/tableprinter.go#L433-L522)).

**Placeholders.** Depending on the path a missing value shows as empty, `<none>` (only in `-o custom-columns`), `<unknown>` (a zero timestamp) or `<invalid>` (an unparsable date). A cell with an embedded newline is cut there and gets `...` ([tableprinter.go L332-L358](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/cli-runtime/pkg/printers/tableprinter.go#L332-L358)).

**Sort.** `--sort-by` evaluates a JSONPath against the full object, not the cell ([sorter.go L385-L415](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/kubectl/pkg/cmd/get/sorter.go#L385-L415)). Strings compare by Go `<` (byte, so code point, order) unless both parse as Quantities; mixed types make `klog.Exitf` end the process ([sorter.go L172-L292](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/kubectl/pkg/cmd/get/sorter.go#L172-L292)). A missing value is "less" even against another missing value, which is not a strict weak order, under the unstable `sort.Sort` ([sorter.go L359-L383](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/kubectl/pkg/cmd/get/sorter.go#L359-L383)).

**Visibility and width.** A column with `priority != 0` is skipped unless the output is `wide` ([tableprinter.go L182-L326](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/cli-runtime/pkg/printers/tableprinter.go#L182-L326)). Widths come from a tabwriter (minwidth 6, padding 3) that remembers each column's widest cell across its flushes every 100 rows; the header is pre-padded to the widest cell of the batch first ([tabwriter.go L25-L36](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/cli-runtime/pkg/printers/tabwriter.go#L25-L36)). The pre-pad measures bytes and the tabwriter runes, so neither measures display width.

## k9s

**Generic rendering.** A resource k9s has no renderer for gets the server Table ([model/helpers.go L32-L45](https://github.com/derailed/k9s/blob/v0.51.0/internal/model/helpers.go#L32-L45)). It uppercases headers, marks `priority > 0` columns as wide and treats a column as time only when it is named `Age`, `Last Seen` or `First Seen`: the server's `type` and `format` are ignored ([render/table.go L66-L84](https://github.com/derailed/k9s/blob/v0.51.0/internal/render/table.go#L66-L84)). Cells are `fmt.Sprintf("%v")`, with `nil` as blank ([render/table.go L112-L163](https://github.com/derailed/k9s/blob/v0.51.0/internal/render/table.go#L112-L163)). `Ctrl-W` toggles wide mode.

**Custom views.** `views.yaml` names columns as `NAME[:jsonpath-or-jq][|flags]`, with flags for time, wide, show, hide and alignment, plus a default sort column; built-in columns a view leaves out are appended as wide ([render/cust_col.go L17-L70](https://github.com/derailed/k9s/blob/v0.51.0/internal/render/cust_col.go#L17-L70), [README L737-L811](https://github.com/derailed/k9s/blob/v0.51.0/README.md#L737-L811)).

**Sort.** The comparator is chosen from header attributes only (time sorts as a duration, capacity as a quantity), never from the column type, so a CRD's `integer` column sorts by natural string order ([model1/table_data.go L107-L120](https://github.com/derailed/k9s/blob/v0.51.0/internal/model1/table_data.go#L107-L120)). Natural order compares digit runs numerically and other bytes bytewise, empty first; ties fall back to the row ID ([model1/helpers.go L170-L204](https://github.com/derailed/k9s/blob/v0.51.0/internal/model1/helpers.go#L170-L204)). From the code (not run), `-5` sorts after `3`.

**Actions.** A view holds a map from key to `KeyAction{Description, Action, Opts{Visible, Shared, Plugin, HotKey, Dangerous}}`; views stack "extenders" that add keys, and every generic resource gets scale and jump-to-owner ([ui/action.go L23-L47](https://github.com/derailed/k9s/blob/v0.51.0/internal/ui/action.go#L23-L47), [view/command.go L315-L334](https://github.com/derailed/k9s/blob/v0.51.0/internal/view/command.go#L315-L334)). The hint bar lists the non-shared actions sorted by key, and read-only mode strips every `Dangerous` one ([ui/action.go L159-L220](https://github.com/derailed/k9s/blob/v0.51.0/internal/ui/action.go#L159-L220)). Plugins are user-owned YAML: `scopes`, `shortCut`, `description`, `command`, `args`, `confirm`, `background`, `dangerous`, `inputs` ([config/plugin.go L54-L80](https://github.com/derailed/k9s/blob/v0.51.0/internal/config/plugin.go#L54-L80)). Args are templated from the selected row: `$NAMESPACE`, `$NAME` and `$COL-<HEADER>` for every column, wide ones included ([view/helpers.go L110-L124](https://github.com/derailed/k9s/blob/v0.51.0/internal/view/helpers.go#L110-L124)). Plugins see one row only; marked rows (Space) reach only built-ins such as delete and scale ([view/browser.go L485-L494](https://github.com/derailed/k9s/blob/v0.51.0/internal/view/browser.go#L485-L494)).

**Drill down.** Enter first checks `jumps.yaml`, which maps a target resource to label or field selectors templated from the selected object, then runs the view's own enter function, describe by default ([view/browser.go L454-L476](https://github.com/derailed/k9s/blob/v0.51.0/internal/view/browser.go#L454-L476)). Deployment to pods is by label selector, hand-coded ([view/dp.go L79-L107](https://github.com/derailed/k9s/blob/v0.51.0/internal/view/dp.go#L79-L107)). Shift-J follows `ownerReferences` upward on any resource, asking which owner when there are several ([view/owner_extender.go L39-L117](https://github.com/derailed/k9s/blob/v0.51.0/internal/view/owner_extender.go#L39-L117)). `:xray` is hand-written per type and refuses others.

## Datasette

**Formatting.** One function renders every cell, trying in order: the column's assigned column type, the `render_cell` plugin hook (first non-empty result wins), bytes as `<Binary: N bytes>` linked to a download, an expanded foreign key as a link, `""` or `None` as `&nbsp;`, a bare http(s) URL as a link, and otherwise `str(value)` truncated ([views/table.py L794-L873](https://github.com/simonw/datasette/blob/1.0a41/datasette/views/table.py#L794-L873)). So NULL and the empty string look the same; only the `<td>` class (`type-none` or `type-str`) tells them apart. Numbers get no locale formatting, booleans (0 and 1) and dates no special case. The 1.0 alphas add column types (`url`, `email`, `json`, `textarea`), assigned per column, each with `render_cell`, `validate` and `transform_value` ([column_types.py L35-L81](https://github.com/simonw/datasette/blob/1.0a41/datasette/column_types.py#L35-L81)). Unit conversion with Pint was removed in 1.0a16 ([changelog L673-L680](https://github.com/simonw/datasette/blob/1.0a41/docs/changelog.rst#L673-L680)).

**Sort.** `_sort` or `_sort_desc` on one column, generated as plain `order by col [desc]`, so SQLite decides: nulls first ascending and last descending ([SQLite ORDER BY](https://www.sqlite.org/lang_select.html#the_order_by_clause)), storage classes NULL < INTEGER and REAL < TEXT < BLOB, text by `BINARY` collation, which is `memcmp` ([SQLite sort order](https://www.sqlite.org/datatype3.html#sort_order)). The keyset cursor encodes NULL as `$null` and writes clauses that match SQLite's null placement ([views/table.py L2145-L2211](https://github.com/simonw/datasette/blob/1.0a41/datasette/views/table.py#L2145-L2211)). From reading the code, the primary-key tie-breaker is added only for continuation pages, so ties on page one are in undefined order.

**Visibility.** `_col` and `_nocol` choose columns but never hide the primary key ([views/table.py L1668-L1697](https://github.com/simonw/datasette/blob/1.0a41/datasette/views/table.py#L1668-L1697)). Facets are suggested from a sample of 1000 rows when a column has few distinct non-null values, with array and date facets detected from the first 100 values ([facets.py L155-L202](https://github.com/simonw/datasette/blob/1.0a41/datasette/facets.py#L155-L202)). There is no width logic: cells wrap, and below 576 px rows become cards.

**Actions.** Plugins implement `row_actions`, `table_actions`, `view_actions`, `query_actions`, `database_actions` and `homepage_actions` ([hookspecs.py L164-L191](https://github.com/simonw/datasette/blob/1.0a41/datasette/hookspecs.py#L164-L191)). Each returns a list of `{href, label, description?}` links or `{type: "button", label, description?, attrs?}` buttons that plugin JavaScript binds by their `data-*` attributes ([plugin hooks docs L1938-L2019](https://github.com/simonw/datasette/blob/1.0a41/docs/plugin_hooks.rst#L1938-L2019)). They appear in one "actions" menu per page. `row_actions` runs only on the single-row page, with that one row ([views/row.py L564-L575](https://github.com/simonw/datasette/blob/1.0a41/datasette/views/row.py#L564-L575)); the table page's per-row Edit and Delete icons are core's, gated on permissions ([views/table.py L755-L775](https://github.com/simonw/datasette/blob/1.0a41/datasette/views/table.py#L755-L775)). The plugin checks permissions itself. Writes go through a JSON API: `insert`, `upsert`, and `update` and `delete` on a row's URL ([JSON write API](https://docs.datasette.io/en/latest/json_api.html#the-json-write-api)).

**Drill down.** A foreign key cell links to the referenced row and shows a label from the target's `label_column`, guessed when unset: the only unique text column, then `name` or `title` ([database.py L1067-L1113](https://github.com/simonw/datasette/blob/1.0a41/datasette/database.py#L1067-L1113)). The row page counts incoming references ("N rows from col in table") and links each to `other_table?col=pk`, a pre-filtered table, skipping ones the user may not view and giving up on timeout ([views/row.py L658-L713](https://github.com/simonw/datasette/blob/1.0a41/datasette/views/row.py#L658-L713)). Facet values are links that add the filter.

## Grafana data frames and the Table panel

**Types and formatting.** `FieldType` is `time`, `number`, `string`, `boolean`, `enum`, `other` (objects and arrays), `frame` and a few more ([dataFrame.ts L13-L29](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/types/dataFrame.ts#L13-L29)). `FieldConfig` carries `unit`, `decimals`, `min`, `max`, `displayName`, `mappings`, `thresholds`, `noValue`, `links`, `actions` and enum labels ([dataFrame.ts L37-L126](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/types/dataFrame.ts#L37-L126)). One display processor turns a value into `{text, numeric, prefix, suffix, color, icon}` ([displayProcessor.ts L42-L216](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/field/displayProcessor.ts#L42-L216)):

1. a default unit by type: absolute date-time in the dashboard's zone for time fields, `bool` for booleans, `string` for strings;
2. value mappings, tried in order, which can set text, color and icon (value, range, regex, and special values null, NaN, true, false, empty);
3. enum labels by index when there are no mappings;
4. the unit formatter for anything numeric;
5. arrays joined with `, `, everything else stringified, and an empty result replaced by `noValue` or `''`. So null and `""` look the same; NaN shows as `NaN` unless mapped (from the code, not run).

The unit registry is total: an unknown unit id becomes a literal suffix, and prefixed ids such as `suffix:`, `si:`, `currency:` and `time:<pattern>` parse ([valueFormats.ts L220-L290](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/valueFormats/valueFormats.ts#L220-L290)). Relative time is a unit, `dateTimeFromNow`, and it is the one formatter whose output is never cached, because it goes stale ([fieldOverrides.ts L182-L201](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/field/fieldOverrides.ts#L182-L201)). The table shows `other` values as pretty-printed JSON in a monospace font ([TableNG/utils.ts L985-L1005](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-ui/src/components/Table/TableNG/utils.ts#L985-L1005)).

**Sort.** On raw values, so mappings and units never change the order ([TableNG/utils.ts L678-L710](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-ui/src/components/Table/TableNG/utils.ts#L678-L710)). Time, number and boolean compare numerically with null always least, so first ascending and last descending; strings, enums and everything else go through `Intl.Collator('en', {sensitivity: 'base', numeric: true})` on `String(v ?? '')`, which is case-insensitive natural order in a fixed English locale ([TableNG/utils.ts L715-L751](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-ui/src/components/Table/TableNG/utils.ts#L715-L751)).

**Visibility, width and alignment.** A field is hidden by an override, `custom.hideFrom.viz`, but stays in the frame for tooltips, styling and link templates ([TableNG/utils.ts L900-L902](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-ui/src/components/Table/TableNG/utils.ts#L900-L902)). Width is a fixed `custom.width` or an even share of what is left, at least 150 px; content is not measured ([TableNG/utils.ts L925-L950](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-ui/src/components/Table/TableNG/utils.ts#L925-L950)). Auto alignment is right for number fields in text cells and left otherwise ([TableNG/utils.ts L423-L446](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-ui/src/components/Table/TableNG/utils.ts#L423-L446)).

**Actions.** Two kinds, both on a field, so both per cell. A data link is `{title, url, targetBlank, internal?, oneClick?}` ([dataLink.ts L34-L62](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/types/dataLink.ts#L34-L62)) whose URL is templated per row: `${__value.raw}`, `${__data.fields.<name>}` and so on, URL-encoded ([fieldOverrides.ts L482-L569](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/field/fieldOverrides.ts#L482-L569)). `${__data.fields.X}` yields the *formatted* value, not the raw one ([getFieldDisplayValuesProxy.ts L19-L61](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/field/getFieldDisplayValuesProxy.ts#L19-L61)). An action is `{type: 'fetch', title, fetch: {method, url, body, queryParams, headers}, confirmation?, variables?}`, a POST by default ([action.ts L5-L88](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/types/action.ts#L5-L88)), sent with a default confirmation "Are you sure you want to <title>?", an `X-Grafana-Action: 1` header and a success or error toast ([actions/utils.ts L58-L146](https://github.com/grafana/grafana/blob/v12.4.14/public/app/features/actions/utils.ts#L58-L146)). Actions show only when the panel context allows ([TableNG.tsx L145-L155](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-ui/src/components/Table/TableNG/TableNG.tsx#L145-L155)). Discovery: a cell with exactly one link and no action is a plain anchor; otherwise a click opens a menu of that cell's links and actions at the pointer ([MaybeWrapWithLink.tsx L15-L36](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-ui/src/components/Table/TableNG/components/MaybeWrapWithLink.tsx#L15-L36)). The `actions` and `data-links` cell types list them inline instead. There are no row-level or multi-row actions.

**Drill down.** A link to another dashboard is a URL with variables. An internal link `{datasourceUid, query}` names a query against another data source and opens it in Explore, optionally split beside the panel ([dataLinks.ts L38-L110](https://github.com/grafana/grafana/blob/v12.4.14/packages/grafana-data/src/utils/dataLinks.ts#L38-L110)).

## Perspective

**Types and formatting.** A column has exactly one of `integer`, `float`, `string`, `boolean`, `date` and `datetime`, fixed when the table is created; updates are coerced ([schema.md L3-L33](https://github.com/finos/perspective/blob/v3.8.0/docs/md/explanation/table/schema.md#L3-L33)). The datagrid formats numbers with `Intl.NumberFormat` in the browser's locale (floats with exactly two decimals), datetimes with `Intl.DateTimeFormat` short date and medium time in the browser's zone, dates pinned to UTC, booleans as `true`/`false`, strings raw ([formatter_cache.js L13-L205](https://github.com/finos/perspective/blob/v3.8.0/packages/perspective-viewer-datagrid/src/js/data_listener/formatter_cache.js#L13-L205)). Per-column `columns_config` overrides the number format, date fields and time zone, and adds color modes (foreground, background, bar, gradient) and string formats (link, bold, italics) ([columns_config.rs L33-L54](https://github.com/finos/perspective/blob/v3.8.0/rust/perspective-viewer/src/rust/config/columns_config.rs#L33-L54)). Null renders as a themeable `-` from CSS, distinct from a blank empty string ([pro.less L192-L195](https://github.com/finos/perspective/blob/v3.8.0/packages/perspective-viewer-datagrid/src/less/pro.less#L192-L195)).

**Sort.** Directions are `asc`, `desc`, `asc abs` and `desc abs`, plus `col` variants that order pivoted column groups ([sort.md L3-L9](https://github.com/finos/perspective/blob/v3.8.0/docs/md/explanation/view/config/sort.md#L3-L9)). Ties break on insertion order, then primary key ([multi_sort.h L87-L161](https://github.com/finos/perspective/blob/v3.8.0/rust/perspective-server/cpp/perspective/src/include/perspective/multi_sort.h#L87-L161)). Strings compare with `strcmp`, code-point order ([scalar.h L36-L44](https://github.com/finos/perspective/blob/v3.8.0/rust/perspective-server/cpp/perspective/src/include/perspective/scalar.h#L36-L44)). NaN is first ascending and last descending ([multi_sort.cpp L153-L208](https://github.com/finos/perspective/blob/v3.8.0/rust/perspective-server/cpp/perspective/src/cpp/multi_sort.cpp#L153-L208)); nulls carry an invalid status that sorts below valid values, so they too come first ascending (inferred from the comparator).

**Alignment.** Numeric cells and headers are right-aligned, everything else left ([table_cell/index.js L99-L100](https://github.com/finos/perspective/blob/v3.8.0/packages/perspective-viewer-datagrid/src/js/style_handlers/table_cell/index.js#L99-L100)).

**Actions and drill down.** The datagrid has no action menu and no context-menu handler. It emits events and leaves the rest to the host. `perspective-click` carries `{row, column_names, config}`, where `config.filter` is the current filter plus one equality per group-by level of the clicked row ([dispatch_click.js L15-L33](https://github.com/finos/perspective/blob/v3.8.0/packages/perspective-viewer-datagrid/src/js/event_handlers/dispatch_click.js#L15-L33), [get_cell_config.js L13-L51](https://github.com/finos/perspective/blob/v3.8.0/packages/perspective-viewer-datagrid/src/js/get_cell_config.js#L13-L51)); the documented drill-down is `viewer.restore(event.detail.config)` ([events.md L22-L39](https://github.com/finos/perspective/blob/v3.8.0/docs/md/how_to/javascript/events.md#L22-L39)). With `selectable` set, `perspective-select` reports single-row selection the same way ([row_select_click.js L15-L70](https://github.com/finos/perspective/blob/v3.8.0/packages/perspective-viewer-datagrid/src/js/event_handlers/row_select_click.js#L15-L70)). This is the same shape as binnacle's Drill-Down Spec.

## VisiData

**Types.** Columns start untyped (`anytype`) and the user types them with a key: `~` text, `#` int, `%` float, `$` currency, `@` date ([sheets.py L1328-L1332](https://github.com/saulpw/visidata/blob/v3.5/visidata/sheets.py#L1328-L1332), [type_currency.py L32](https://github.com/saulpw/visidata/blob/v3.5/visidata/type_currency.py#L32), [type_date.py L130](https://github.com/saulpw/visidata/blob/v3.5/visidata/type_date.py#L130)). A type is a conversion callable plus an icon and a default format; floats default to `{:.2f}`, dates to `%Y-%m-%d` ([_types.py L16-L98](https://github.com/saulpw/visidata/blob/v3.5/visidata/_types.py#L16-L98)). Nested dicts and lists show as JSON, and `(` expands a column into its keys one level at a time, sampling rows and hiding the parent ([features/expand_cols.py L25-L62](https://github.com/saulpw/visidata/blob/v3.5/visidata/features/expand_cols.py#L25-L62)).

**Null, error and empty.** Every typed read wraps None and exceptions instead of raising ([wrappers.py L98-L110](https://github.com/saulpw/visidata/blob/v3.5/visidata/wrappers.py#L98-L110)), and the cell keeps the reason as a one-character note: `⌀` for None, `!` for a read or conversion error (showing the raw value), `?` for a format error, `:` while pending ([column.py L385-L446](https://github.com/saulpw/visidata/blob/v3.5/visidata/column.py#L385-L446)). An empty string is blank with no note, except in a numeric column, where it is a conversion error.

**Sort.** The key is the list of typed values, descending ones wrapped to reverse `<`, under Python's stable sort; a `TypeError` from mixed types stops the sort with a warning to set the column type ([sort.py L116-L144](https://github.com/saulpw/visidata/blob/v3.5/visidata/sort.py#L116-L144)). Wrapped values (None and errors) are always least ([wrappers.py L40-L42](https://github.com/saulpw/visidata/blob/v3.5/visidata/wrappers.py#L40-L42)). Text compares by code point.

**Width and visibility.** Key columns are pinned left ([sheets.py L468-L483](https://github.com/saulpw/visidata/blob/v3.5/visidata/sheets.py#L468-L483)). Auto width is the widest of header and cells plus 2, measured over the first 1000 rows (or only the visible rows beyond that), capped at 20 except for the last column ([column.py L519-L549](https://github.com/saulpw/visidata/blob/v3.5/visidata/column.py#L519-L549)). `-` hides a column, `g-` hides every column with one value.

**Actions.** A command is a long name, Python to run in the sheet's scope, and help text, registered per sheet class; keys bind to long names, and lookup walks the sheet's class hierarchy ([settings.py L364-L444](https://github.com/saulpw/visidata/blob/v3.5/visidata/settings.py#L364-L444)). One row and many rows are separate commands by convention: `d` deletes the current row, `gd` the selected rows ([clipboard.py L207-L210](https://github.com/saulpw/visidata/blob/v3.5/visidata/clipboard.py#L207-L210)). A file listing adds its own (`Enter` opens a file, `gEnter` the selected ones; [shell.py L307-L321](https://github.com/saulpw/visidata/blob/v3.5/visidata/shell.py#L307-L321)) and defers deletes: `d` only marks the row, and the change happens on an explicit commit ([shell.py L274-L278](https://github.com/saulpw/visidata/blob/v3.5/visidata/shell.py#L274-L278)). Because every command has a long name, `Space` gives a fuzzy command palette and menus are paths to long names, for free ([features/cmdpalette.py L258-L266](https://github.com/saulpw/visidata/blob/v3.5/visidata/features/cmdpalette.py#L258-L266), [menu.py L83-L103](https://github.com/saulpw/visidata/blob/v3.5/visidata/menu.py#L83-L103)).

**Drill down.** `Enter` runs `open-row`, which pushes whatever the sheet's `openRow(row)` returns; the default is the row transposed into a column-and-value sheet ([pyobj.py L232-L260](https://github.com/saulpw/visidata/blob/v3.5/visidata/pyobj.py#L232-L260), [pyobj.py L314-L318](https://github.com/saulpw/visidata/blob/v3.5/visidata/pyobj.py#L314-L318)). A sheet type overrides `openRow` or `openCell` to dive somewhere else.

## Across the viewers, by question

**Default formatting by type.** Every viewer that knows a column's type formats from the type plus a small set of column properties (unit, decimals, format pattern), and only Grafana and Perspective localise numbers. Units work best as a total registry: Grafana never fails on an unknown unit and falls back to a suffix. Relative time is a display choice applied at render time (Grafana's `dateTimeFromNow`, k9s's age) except in kubectl's CRD path, where the server freezes an age string into the response so it cannot be sorted or refreshed. Booleans are `true`/`false` text everywhere except where a mapping relabels them. Nested values are JSON text (Grafana, VisiData), Go syntax (kubectl custom columns, k9s) or dropped (kubectl CRD columns that are not strings); VisiData alone lets the user expand them into columns.

**Null versus empty.** Kubectl, k9s, Datasette and Grafana all render null and the empty string alike. Perspective (`-`) and VisiData (`⌀`, plus `!` for errors) keep them apart, and VisiData also keeps a third state, a value that failed to convert, which is what a typed column over loosely typed JSON produces.

**Sort.** Four of six put nulls first ascending and last descending (SQLite, Grafana, Perspective, VisiData); none puts them last in both directions, as binnacle-memory does (`crates/binnacle-memory/src/sort_keys.rs:6-11`). Text is code point order in kubectl, Datasette, Perspective and VisiData; Grafana uses a fixed-locale natural collator and k9s a bytewise natural sort. Mixed types are where viewers fail: kubectl exits, VisiData stops, Grafana and k9s silently compare strings. The two that never fail fix one type per column (Perspective) or define a total order across storage classes (SQLite). Ties need a key tie-breaker; Datasette's first page and kubectl's missing values show what happens without one.

**Hidden, shown, width.** Priority as a visibility tier (kubectl's `priority > 0`, toggled as "wide") is the only per-column default that the data's owner sets; everything else is a viewer override (k9s views, Datasette `_nocol`, Grafana's hide override, VisiData's `-`). Grafana keeps hidden fields addressable for templates and tooltips. Widths are either measured from a sample (kubectl, k9s, VisiData, with VisiData capping at 20 columns of text) or not measured at all (Grafana, Datasette). Only character-cell viewers measure, and none of them measures display width.

**Row actions.** The owner of the data describes actions in Datasette (plugin hooks per page level), Grafana (links and HTTP actions per field) and VisiData (commands per sheet class); in k9s the user describes them; Perspective describes none and leaves it to the host's events. The shared record is a name, a label, help text and, for something with side effects, a confirmation and a permission check (k9s's `dangerous`, Grafana's `canExecuteActions`, Datasette's plugin-side `allowed`). Invocation is either a templated request built from the row's values (k9s `$COL-x`, Grafana `${__data.fields.x}`) or a named callback the host runs with the row (VisiData, Datasette buttons, Perspective events). Discovery is a hint bar or menu keyed per view (k9s, VisiData), one menu per page (Datasette) or a menu at the clicked cell, collapsing to a plain link when there is only one (Grafana). Multi-row actions exist only in VisiData (a `g` variant over selected rows) and in k9s's built-ins; none of the plugin systems passes a selection.

**Drill down.** Three shapes: a forward link from a reference to the target row (Datasette foreign keys, Grafana links); the reverse, "rows elsewhere that point here", as a filtered table (Datasette's incoming counts, k9s selectors and `jumps.yaml`); and a host-defined dive from the current row (VisiData `openRow`, Perspective's event with a filter to restore). k9s shows the cost of not describing references: CRDs get only describe and owner-up.

## What binnacle can borrow

### #284: where the source lives, and its seam

- **Keep raw and display values apart in the source.** Grafana sorts raw values and formats separately; Datasette keeps the raw value beside the rendered one. The described-table source should hold each cell as the decoded JSON value plus its column type, give the In-Memory Table Source typed sort keys from it, and hand renderers display text from a separate step, so mappings and units never change order.
- **Take the type from the description, never from the values.** k9s's name-guessing and Grafana's first-value guessing are what the Frictionless `type` makes unnecessary. A value that does not match its column's type should be a third cell state (VisiData's conversion error), not a silent null (kubectl's CRD convertor).
- **Total, stable order with the Key as tie-breaker.** Every viewer without one (kubectl's missing values, Datasette's first page) shows unstable order; Perspective and k9s break ties by key. The source already has the primary-key tuple, so a final tie-break on it is free.
- **A filter that reproduces a row's context is enough for a host to drill down.** Perspective's click event carries the row plus a filter to restore; binnacle's Drill-Down Spec is the same idea for Summary Items, and a described source can offer the equivalent for a Leaf: the row's Key and primary-key values.

### #285: ordering and default display

- **Nulls: first ascending, last descending is the majority.** SQLite, Grafana, Perspective and VisiData all do this, and ADR 0067's "null lowest" is the same rule. binnacle-memory's "last in both directions" matches none of the six. If binnacle keeps its rule, it is the one that should be configurable per source; if it moves, ADR 0067 and the majority agree.
- **Code point text order is the norm,** in kubectl, Datasette, Perspective and VisiData, and it is what ADR 0067 says. Locale or natural order (Grafana, k9s) is a display option a host opts into, and Grafana shows the cost of doing it implicitly: a fixed `en` locale that ignores the user's.
- **Define mixed and NaN order rather than failing.** Perspective's NaN-first and SQLite's storage-class order are the two working precedents; binnacle-memory already puts NaN after numbers, so pick one rule and state it with the null rule.
- **Show null, empty and invalid differently.** A themeable null glyph (Perspective's `-`, VisiData's `⌀`), blank for `""`, and a mark for a value that failed its type (VisiData's `!`). Four of the six viewers lose the difference, and flotilla's rows are JSON, where `null`, `""` and a mismatched value all occur.
- **Format from type plus a total unit table.** Integers and numbers right-aligned (Grafana, Perspective, VisiData), floats with fixed decimals, UCUM `unit` mapped through a registry where an unknown code falls back to a literal suffix (Grafana's rule). Datetimes keep their timestamp and render relative or absolute at draw time, never frozen (kubectl's CRD age is the counter-example), with relative text refreshed and absolute text in a stated zone. Categories show their label. `object` columns show compact JSON, clipped, as Grafana and VisiData do; hiding them by default is reasonable because no viewer can sort them.
- **Visibility tiers from the description.** kubectl's priority is the only owner-set visibility default in the survey, and it maps onto `roles` (key and state shown, `object` and wide columns hidden until asked for). Grafana's point that a hidden column stays available to actions and templates applies to row actions here.

### #288: the CLI host

- **kubectl's printer is the reference for piped text:** uppercase or `title` headers, tab-aligned columns sized by content with a pre-scan of the first batch, cells cut at embedded newlines with an ellipsis, hidden-priority columns behind a "wide" switch, and one empty rendering for null. Improve on it by measuring display width (both kubectl and k9s measure bytes or runes) and by capping wide columns as VisiData does.
- **Formatting must be the same function in every host,** or the CLI drifts from the TUI and the web the way kubectl's `custom-columns` (Go map syntax, `<none>`) drifts from its table printer (empty, JSON for strings). That argues for the formatter living in a shared crate, not in each adapter.
- **Column and sort flags as one shared grammar.** kubectl's `-o custom-columns=HEADER:path` and `--sort-by`, Datasette's `_col`, `_nocol` and `_sort` as URL state, and k9s's `views.yaml` all express a view as data; a View Spec argument shared across commands is the same idea.

### #289: host-defined row actions

- **An action record:** a stable name, a label, a help line, an optional key, whether it takes one row or the picks, whether it needs confirmation, and whether it is dangerous (hidden in a read-only grid). Every field has a precedent: VisiData's long name and help, k9s's `shortCut`, `confirm` and `dangerous`, Grafana's `confirmation`, Datasette's label and description.
- **Name actions, bind keys to names.** VisiData shows that a long name per command gives a command palette, menus and key bindings from one list. binnacle's Action term already means a semantic input, so a row action reaching the Grid could be one Action ("invoke action N") that the Grid turns into an Effect naming the action and the rows' Keys; the host keymap and palette bind to the name.
- **One row and many rows are different entries,** not one action with a mode: VisiData's `d` and `gd`. None of the plugin systems (k9s, Datasette, Grafana) passes a selection, so this is a gap binnacle fills rather than copies.
- **Discovery: a per-row menu that collapses to a direct gesture when there is one entry.** Grafana's single-link-is-an-anchor rule fits binnacle's Activate gesture as the default action, with a row menu for the rest and the host's palette for all of them.
- **Pass Keys, not formatted values.** Grafana's `${__data.fields.X}` silently yields formatted text; k9s passes rendered column strings. The Effect should carry Keys, and the host reads raw values from the source.
- **Pending and failed rows have precedent only in VisiData's deferred commit** (a delete marks the row until committed). Grafana's toast after an HTTP action is the minimum. For flotilla, an `upsert` or `delete` arriving later settles the row, so a pending mark keyed by Key until then is binnacle's to add.
- **What flotilla's action description needs to say,** from the survey: name, label, description, arity (row or picks), the columns or key it needs, confirmation text, and whether it changes state. Drilling by foreign key fits the same record as an action whose result is "open table T filtered by these columns", which Datasette's forward links and incoming counts show is enough for both directions.
